# 企业管理决策投影平台

企业管理决策投影平台是一套面向企业核心管理层的数字化管理系统。

平台通过问卷、访谈、制度文件、日常管理信息以及 ERP、MES、CRM、财务等业务系统，建立企业在数字世界中的完整投影，帮助管理层理解企业结构、识别潜在问题、统一企业数据、制定管理方案并跟踪执行结果。

本平台不替代 ERP、MES 或其他业务系统，而是位于这些系统之上，负责企业建模、语义统一、管理分析、决策协作和行动闭环。

## 核心理念

企业信息分为三个层次：

1. 企业设计层  
   描述企业应该如何运作，包括组织、岗位、职责、权限、流程、战略、考核以及信息流、资金流、物流和指令流。

2. 企业运行层  
   描述企业实际发生了什么，包括订单、采购、库存、生产、交付、回款、绩效和其他业务数据。

3. 企业潜在层  
   描述暂时无法直接证明，但值得管理层持续研究的问题和关系，例如非正式影响、知识依赖、利益博弈、风险传导和组织设计中的结构性矛盾。

平台通过本体层把三个层次连接起来，同时保持事实、观察和假设之间的边界。

## 产品组成

平台分为开发端和管理端。

### 开发端

开发人员、调研人员和企业实施人员使用开发端完成：

- 创建企业和解读项目
- 导入问卷、访谈和制度材料
- 建立企业组织与岗位模型
- 建立岗位职责、权限和流程关系
- 建立战略、能力、流程与绩效之间的关系
- 使用关系图查看企业整体结构
- 发布企业投影版本
- 接入 ERP、MES、CRM 和财务系统
- 配置对象、字段、身份和关系映射
- 处理数据冲突
- 创建统一语义数据集
- 验证数据与企业模型的一致性
- 管理模型版本、数据版本和来源关系

开发端负责建立可靠的企业基础。

### 管理端

企业核心管理层使用管理端完成：

- 查询企业结构和业务数据
- 输入会议纪要、工作汇报和管理观察
- 查询部门、岗位、职责、权限和流程
- 分析战略、考核与企业结果之间的关系
- 发现组织设计和实际运行之间的偏差
- 探索潜在问题和隐藏联系
- 比较不同管理方案
- 创建和推进管理行动
- 查看行动执行结果
- 确认潜在问题并沉淀为企业知识
- 根据新结果重新评估过去的判断

管理端以统一对话窗口为入口，用户不需要理解后台 Agent、数据库或工具的技术结构。

## Agent 架构

平台使用四类核心 Agent。

### 企业建模 Agent

负责从问卷、访谈、制度和调研材料中提取稳定的企业结构。

主要能力：

- 识别部门、岗位和业务对象
- 提取岗位职责和权限
- 建立岗位、流程、部门和战略关系
- 识别信息流、资金流、物流和指令流
- 建立绩效指标与职责、战略的关系
- 生成企业模型草稿
- 根据人工修改重新生成模型
- 提交模型变更并等待确认

它不能把不确定推测直接写入正式企业模型。

### 系统本体 Agent

负责将企业正在使用的各类信息系统映射到企业模型。

主要能力：

- 读取系统结构和字段
- 识别业务对象
- 建议字段和对象映射
- 对齐不同系统中的同一客户、物料、订单、员工或设备
- 处理单位、金额、状态和时间口径差异
- 识别重复对象和冲突记录
- 建立系统数据与企业对象之间的关系
- 生成统一语义数据集
- 保留完整数据来源和血缘
- 对同步结果进行校验

它只能根据字段、规则、映射和来源执行确定性处理，不能凭名称相似度擅自合并对象。

### 管理输入 Agent

负责吸收企业日常发生的高频管理信息。

主要输入：

- 会议纪要
- 工作汇报
- 绩效反馈
- 异常记录
- 管理者补充说明
- 部门之间的不同陈述
- 企业实际运行中的非正式信息

主要能力：

- 保存原始信息
- 提取事件、观察、评价和诉求
- 关联企业对象
- 识别重复信息
- 记录矛盾陈述
- 标记信息发生时间
- 提出待调查问题
- 形成管理观察

管理输入 Agent 写入管理观察库，不直接修改正式企业模型。

### 管理输出 Agent

负责处理管理层提出的查询、分析和执行任务。

它会先判断任务类型：

- 简单任务：可以通过企业模型和正式系统数据确定性完成。
- 复杂任务：需要跨库调查、解释原因、比较方案或寻找潜在问题。

简单任务由程序和确定性工具优先完成。

复杂任务可以调用：

- 正式企业库
- 管理观察库
- 企业潜在库
- 企业模型和关系图
- 统一语义数据集
- 历史行动和执行结果

复杂任务完成后，系统会说明：

- 使用了哪些数据
- 查询了哪些对象和关系
- 使用了哪些时间范围和版本
- 哪些证据支持结论
- 存在哪些冲突和未知信息
- 哪些内容属于分析假设
- 实际执行了哪些动作
- 哪些潜在问题建议保存

## 三类数据存储

### 正式企业库

保存经过确认、可以作为企业正式依据的数据：

- 企业组织和岗位模型
- 职责、权限和流程
- 战略、能力和绩效关系
- 企业对象和对象关系
- 系统语义映射
- 已校验的业务数据
- 正式决策和管理行动

正式企业库是确定性查询和自动化执行的主要依据。

### 管理观察库

保存日常管理信息：

- 会议和汇报
- 观察和异常
- 人员陈述
- 主观评价
- 非正式信息
- 未验证的管理判断
- 信息冲突和待确认事项

管理观察库中的信息不会自动成为企业事实。

### 企业潜在库

保存经管理者认可、值得持续研究的内容：

- 潜在问题
- 潜在关系
- 组织设计矛盾
- 岗位和流程中的代理问题
- 能力和知识依赖
- 利益博弈
- 风险传导
- 因果假设
- 管理经验和历史案例

潜在库的可信度高于管理观察库，低于正式企业库。

“人工认可”与“已经证实”分别记录。潜在库中的假设仍然可能被后续证据推翻。

## 任务处理流程

### 简单任务

例如：

- 查询某段时间的订单金额
- 导出某类客户
- 查询某岗位的正式权限
- 统计已确认的业务指标
- 创建一项明确的管理跟进任务

系统会检查对象、口径、时间、数据完整性和工具前置条件，然后调用确定性程序完成。

### 复杂任务

例如：

- 为什么销售增长但回款下降
- 为什么某流程长期积压
- 某部门是否存在职责与权限不匹配
- 哪些岗位可能存在代理问题
- 如何调整组织结构提高执行效率
- 哪些部门之间存在隐性的风险传导

系统会跨库检索相关信息，沿企业关系图扩展调查，比较正式设计、实际数据、管理观察和历史潜在认识，最后给出结论、替代解释和可执行方案。

新发现的潜在问题必须由管理者确认后才能进入企业潜在库。

## Action 执行体系

平台的所有执行能力都通过统一 Action 引擎完成。

Action 包含：

- 明确的名称和版本
- 输入参数和类型
- 目标对象
- 前置条件
- 数据版本要求
- 是否需要人工确认
- 执行方式
- 成功核验方法
- 失败处理
- 重试规则
- 补偿或撤销方式
- 审计信息

标准执行流程：

```text
识别任务
  ↓
选择处理方式
  ↓
生成结构化动作
  ↓
参数与业务规则校验
  ↓
预演或生成执行计划
  ↓
人工确认
  ↓
执行动作
  ↓
回查结果
  ↓
记录结果与后续反馈
