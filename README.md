# 企业管理决策投影平台

企业管理决策投影平台是一套面向企业核心管理层的数字化管理系统。

平台通过问卷、访谈、制度文件、日常管理信息以及 ERP、MES、CRM、财务等业务系统，建立企业在数字世界中的完整投影，帮助管理层理解企业结构、识别潜在问题、统一企业数据、制定管理方案并跟踪执行结果。

本平台不替代 ERP、MES 或其他业务系统，而是位于这些系统之上，负责企业建模、语义统一、管理分析、决策协作和行动闭环。

## 核心理念

企业信息分为三个层次：

1. 企业设计层  
   描述企业应该如何运作，包括组织、岗位、职责、权限、流程、战略、考核以及信息流、资金流、物流和指令流。

2. 企业运行层  
   描述企业实际发生了什么，包括订单、采购、库存、生产、交付、回款、绩效和其他业务数据。

3. 企业潜在层  
   描述暂时无法直接证明，但值得管理层持续研究的问题和关系，例如非正式影响、知识依赖、利益博弈、风险传导和组织设计中的结构性矛盾。

平台通过本体层把三个层次连接起来，同时保持事实、观察和假设之间的边界。

## 产品组成

平台分为开发端和管理端。

### 开发端

开发人员、调研人员和企业实施人员使用开发端完成：

- 创建企业并建立统一企业投影
- 导入问卷、访谈和制度材料
- 建立企业组织与岗位模型
- 建立岗位职责、权限和流程关系
- 建立战略、能力、流程与绩效之间的关系
- 使用关系图查看企业整体结构
- 发布企业投影版本
- 接入 ERP、MES、CRM 和财务系统
- 配置对象、字段、身份和关系映射
- 处理数据冲突
- 创建统一语义数据集
- 验证数据与企业模型的一致性
- 管理模型版本、数据版本和来源关系

开发端负责建立可靠的企业基础。

### 管理端

企业核心管理层使用管理端完成：

- 查询企业结构和业务数据
- 输入会议纪要、工作汇报和管理观察
- 查询部门、岗位、职责、权限和流程
- 分析战略、考核与企业结果之间的关系
- 发现组织设计和实际运行之间的偏差
- 探索潜在问题和隐藏联系
- 比较不同管理方案
- 创建和推进管理行动
- 查看行动执行结果
- 确认潜在问题并沉淀为企业知识
- 根据新结果重新评估过去的判断

管理端以统一对话窗口为入口，用户不需要理解后台 Agent、数据库或工具的技术结构。

## Agent 架构

平台只保留两个用户可见的 Agent。它们共用企业目录、来源和运行引擎，但工具权限和写入边界不同。

### 建设 Agent

建设 Agent 有两个内部模式：

- 建模模式：从问卷、访谈、制度和报告提取部门、岗位、职责、权限、流程、战略和指标，生成带来源的模型草稿。
- 接入模式：读取系统结构和样本，建议对象、字段、身份、关系、单位、状态和时间映射，生成可校验的统一数据集。

两种模式使用不同的上下文和工具集合。建设 Agent 只能提交草稿、映射和变更集，不能绕过校验直接发布正式模型，也不能向 ERP、MES、CRM 写入。

### 管理 Agent

管理 Agent 的输入、查询、分析、情景推演和动作执行都在同一个对话窗口内完成：

- 输入阶段保存会议纪要、汇报、异常、绩效结果和管理者观察到观察库，不提升为正式事实。
- 查询阶段优先使用已发布模型和已校验数据；缺少口径或数据时返回明确缺口。
- 复杂分析阶段才跨库读取观察、潜在认识、工作观察和历史情景，区分事实、观察、假设与未知。
- 推演阶段调用类型化情景计算 Action，冻结输入、规则和结果；情景成功不代表现实系统已经执行。
- 潜在问题必须由管理者明确确认后才保存，不能由模型自动升级为正式事实。

所有工具都经过服务端注册、参数校验、范围校验和运行留痕。当前内置 Action 支持平台内保存、查询、导出、变更草稿和情景推演；外部系统写入只通过未来独立连接器扩展。

## 数据存储

默认使用一个物理 SQLite 数据库，正式企业数据、管理观察、潜在认识、系统接入、情景运行和控制记录使用独立逻辑表与服务边界。员工电脑上的独立采集器只保留待上传缓存，不接触平台数据库。

检索采用“结构化条件优先、关系邻域按需展开、原始来源可追溯”的路径：原始系统记录保留完整 JSON，同时建立有限的标量查找索引；索引只负责缩小候选范围，Agent 不能直接遍历数据库或执行任意 SQL。过期导入预览、恢复临时包、未确认工作观察预览和过期导出文件由后台生命周期任务自动清理，也可通过生命周期接口预览后主动删除；正式企业数据不会被该任务删除。

逻辑上仍分为以下数据域：

### 正式企业库

保存经过确认、可以作为企业正式依据的数据：

- 企业组织和岗位模型
- 职责、权限和流程
- 战略、能力和绩效关系
- 企业对象和对象关系
- 系统语义映射
- 已校验的业务数据
- 正式决策和管理行动

正式企业库是确定性查询和自动化执行的主要依据。

### 管理观察库

保存日常管理信息：

- 会议和汇报
- 观察和异常
- 人员陈述
- 主观评价
- 非正式信息
- 未验证的管理判断
- 信息冲突和待确认事项

管理观察库中的信息不会自动成为企业事实。

### 企业潜在库

保存经管理者认可、值得持续研究的内容：

- 潜在问题
- 潜在关系
- 组织设计矛盾
- 岗位和流程中的代理问题
- 能力和知识依赖
- 利益博弈
- 风险传导
- 因果假设
- 管理经验和历史案例

潜在库的可信度高于管理观察库，低于正式企业库。

“人工认可”与“已经证实”分别记录。潜在库中的假设仍然可能被后续证据推翻。

## 任务处理流程

### 简单任务

例如：

- 查询某段时间的订单金额
- 导出某类客户
- 查询某岗位的正式权限
- 统计已确认的业务指标
- 创建一项明确的管理跟进任务

系统会检查对象、口径、时间、数据完整性和工具前置条件，然后调用确定性程序完成。

### 复杂任务

例如：

- 为什么销售增长但回款下降
- 为什么某流程长期积压
- 某部门是否存在职责与权限不匹配
- 哪些岗位可能存在代理问题
- 如何调整组织结构提高执行效率
- 哪些部门之间存在隐性的风险传导

系统会跨库检索相关信息，沿企业关系图扩展调查，比较正式设计、实际数据、管理观察和历史潜在认识，最后给出结论、替代解释和可执行方案。

新发现的潜在问题必须由管理者确认后才能进入企业潜在库。

## Action 执行体系

平台的所有执行能力都通过统一 Action 引擎完成。

Action 包含：

- 明确的名称和版本
- 输入参数和类型
- 目标对象
- 前置条件
- 数据版本要求
- 是否需要人工确认
- 执行方式
- 成功核验方法
- 失败处理
- 重试规则
- 补偿或撤销方式
- 审计信息

标准执行流程：

```text
识别任务
  ↓
选择处理方式
  ↓
生成结构化动作
  ↓
参数与业务规则校验
  ↓
预演或生成执行计划
  ↓
人工确认
  ↓
执行动作
  ↓
回查结果
  ↓
记录结果与后续反馈
