# 26 开发者平台与高管使用者平台拆分计划

## 1. 最终产品边界

本计划冻结两个产品入口，不再按“调研者”和“管理层”拆分项目建设责任：

1. **开发者平台**：由 FDE、顾问、实施人员、数据工程师和平台开发者使用，负责公司与项目创建，以及从调研材料到可发布企业数字投影的绝大部分工作。
2. **高管使用者平台**：由公司董事长、总经理和核心管理层使用，只消费开发者已经发布的企业投影，并通过管理决策 Agent 查询、理解和比较企业信息。

“开发者”在这里指建设企业数字投影的人，不只指编写 Python 或 JavaScript 的程序员。

```text
开发者平台
  创建公司与项目
  导入问卷、报告和系统数据
  建模、映射、校验、修正
  使用企业投影 Agent
  发布管理层可用版本
             ↓ 唯一交界：不可变发布版本
高管使用者平台
  进入已发布公司和项目
  调用管理决策 Agent 查询
  查看答案、依据、版本和数据缺口
```

两端共享领域内核和数据库模型，但必须使用不同前端、不同 API 路由集合和不同 Agent 上下文。不能仅靠隐藏按钮假装已经拆分。

## 2. 与既有方案的关系

本计划在“平台边界、项目归属、Agent 入口和交接方式”方面取代 25 号双 Agent 工作台计划中的同名部分：

- 公司创建、项目创建和项目全生命周期全部属于开发者平台；
- 企业投影 Agent 只属于开发者平台；
- 管理决策 Agent 只属于高管使用者平台；
- 两个 Agent 不在同一页面切换，也不直接建立聊天交接；
- 开发者向高管交付的是已发布投影版本，不是对话摘要；
- 高管不维护投影，也不在管理 Agent 对话中执行项目写操作。

25 号计划中关于两类 Agent 的职责、工具化能力、上下文隔离和历史对话原则继续有效。

## 4. 开发者平台

### 4.1 导航顺序

开发者平台沿用证据优先流程，并收敛成七个用户可理解的阶段；其中企业投影内部明确分为上游设计和可选下游运行数据：

1. **公司与项目**：公司、项目、范围、负责人、初始关切和项目阶段；
2. **材料与调研**：问卷答案 CSV、访谈报告、现场材料和来源；
3. **上游企业设计**：组织、岗位、流程、信息流、资金流、岗位职责和流程工作设计；完成后发布设计基线；
4. **下游系统数据（可选）**：基于指定设计基线创建运行投影，再处理 CSV、系统映射、转换、质量问题和血缘；
5. **投影校验**：完整性、来源、冲突、时效和管理查询就绪度；
6. **企业投影 Agent**：围绕当前项目协助提取、建模、修正和生成变更提案；
7. **发布与交付**：比较草稿与上次发布版本，生成不可变发布版本，并预览高管端效果。

管理诊断、因果模型、管理问题模板和报告模板仍可由开发者维护，但作为企业投影的分析资产，不在高管端显示编辑表单。

### 4.2 企业投影 Agent

企业投影 Agent 可以读取当前开发项目的草稿上下文：

- 项目简报和阶段；
- 问卷答案、调研报告和附件提取结果；
- 当前本体、对象、关系、事件和指标；
- 数据导入、字段映射、身份映射、质量问题和血缘；
- 历史投影版本、当前草稿和发布校验结果。

它只能生成提案、变更集、映射建议和发布建议。正式对象、关系、映射和发布版本仍由开发者确认。

### 4.3 开发者项目主页

项目主页必须直接回答：

- 当前项目在哪个阶段；
- 投影草稿与最新发布版本相差什么；
- 哪些材料尚未处理；
- 哪些映射、冲突或证据阻止发布；
- 最新发布版本何时交付给高管；
- 高管查询中出现了哪些无法回答的数据缺口。

## 5. 高管使用者平台

### 5.1 页面结构

高管端不复制开发者端的工作流导航。第一版只需要：

1. 顶部显示公司、项目、当前发布版本和数据更新时间；
2. 中间是管理决策 Agent 对话；
3. 右侧显示本次回答引用的指标、对象、关系、管理问题和来源；
4. 对话列表支持新建、重命名、删除和恢复；
5. 当只有一个可用项目时自动进入，不要求重复选择；
6. 当存在多个已交付项目时，只允许在已发布项目中切换。

高管端不得出现公司/项目创建、数据导入、本体、映射、变更集、模型密钥、诊断日志和 Agent 运行参数。

### 5.2 管理决策 Agent

第一阶段的管理决策 Agent是只读查询 Agent。它可以：

- 回答企业当前状态、趋势、异常和关键约束；
- 解释对象、关系、指标、事件和管理问题之间的联系；
- 比较已经进入发布版本的方案、风险和历史结果；
- 明确区分事实、推断、假设和缺失数据；
- 提供可点击的来源和版本引用；
- 在信息不足时说明无法回答的原因，并生成数据缺口说明。

它不能：

- 创建或修改公司与项目；
- 读取未发布草稿；
- 修改对象、本体、映射、指标和原始材料；
- 直接创建正式决策和行动；
- 自动把聊天内容写入企业投影；
- 在没有来源时伪装成已经掌握企业事实。

### 5.3 高管对话的版本规则

每个管理对话必须固定一个 `publication_id`：

- 新建对话默认使用最新有效发布版本；
- 开发者发布新版本后，旧对话仍绑定旧版本，回答不会悄悄变化；
- 高管可以新建“使用最新版本”的对话；
- 页面始终显示当前对话所使用的版本号和发布时间；
- 比较两个版本必须显式发起版本比较查询。

## 6. 两端唯一交界：企业投影发布

当前 `projection_versions` 只记录技术变更集序列，`ontology_releases` 只记录本体类型包；两者都不足以定义高管 Agent 的完整只读上下文。

新增 `projection_publications`：

| 字段 | 作用 |
|---|---|
| `id` | 发布版本标识 |
| `project_id` | 所属开发项目 |
| `publication_no` | 项目内递增版本号 |
| `projection_sequence` | 固定投影变更序列 |
| `ontology_release_id` | 固定本体发布包 |
| `status` | `draft`、`published`、`superseded` |
| `readiness_snapshot` | 发布时的校验结果 |
| `context_snapshot` | 项目名称、范围和管理查询边界 |
| `manifest_hash` | 发布内容摘要 |
| `release_note` | 开发者交付说明 |
| `created_at`、`published_at` | 生命周期时间 |

新增 `projection_publication_items`，固定发布时使用的资源版本：

- 对象引用 `object_versions.id`；
- 关系引用 `link_versions.id`；
- 事件、指标和不可变观察引用各自资源 ID；
- 管理问题、因果资产和报告模板引用对应修订或不可变记录；
- 每项记录资源类型、稳定 ID、版本 ID、内容摘要和顺序。

发布过程必须在一个事务内完成：重新运行投影校验、生成清单、计算摘要、写入发布记录、设为 `published`。发布后禁止原地修改，只能创建下一版。

## 7. API 拆分

### 7.1 开发者 API

前缀：`/api/v2/developer`

负责：

- 公司和项目 CRUD；
- 项目简报和阶段推进；
- 调研、附件、对象图、本体、数据接入和血缘；
- 投影校验、变更集和提案审批；
- 企业投影 Agent 对话；
- 发布版本创建、校验、发布、撤下和预览；
- 模型配置、诊断和后台任务。

现有 `/api/v2/companies`、`/projects` 等接口先由兼容路由代理到开发者服务；新前端只调用 developer 前缀。连续一个发布周期无旧调用后再删除兼容路由。

### 7.2 高管 API

前缀：`/api/v2/executive`

第一版端点：

```text
GET    /projects
GET    /projects/{project_id}/active-publication
GET    /publications/{publication_id}/overview
GET    /publications/{publication_id}/sources/{source_type}/{source_id}
GET    /publications/{publication_id}/threads
POST   /publications/{publication_id}/threads
PATCH  /publications/{publication_id}/threads/{thread_id}
DELETE /publications/{publication_id}/threads/{thread_id}
POST   /publications/{publication_id}/threads/{thread_id}/messages
POST   /publications/{publication_id}/threads/{thread_id}/query
```

高管路由不包含公司/项目创建以及任何企业投影写接口。

### 7.3 运行时边界

增加 `EIP_SURFACE`：

- `developer`：挂载开发者前端和开发者 API；
- `executive`：只挂载高管前端和高管 API；
- `all_in_one_dev`：本地开发测试时同时挂载两端。

这样高管部署不是简单隐藏开发者按钮，而是根本不挂载开发者写路由。第一阶段保持同一代码库和同一领域内核，不拆微服务。

## 8. 前端目录和入口

```text
src/enterprise_insight/web/
  static_developer/
    index.html
    app.js
    styles.css
  static_executive/
    index.html
    app.js
    styles.css
```

入口：

- `/developer/`：开发者平台；
- `/executive/`：高管使用者平台；
- `/`：本地开发模式跳转 `/developer/`；高管部署直接跳转 `/executive/`。

开发者端与高管端已经使用各自独立的静态资源目录，不在同一个 `app.js` 中增加显示/隐藏分支。

## 9. Agent 与对话数据调整

### 9.1 对话类型

正式保留：

- `projection`：开发者端企业投影 Agent；
- `management`：高管端管理决策 Agent。

`agent_threads` 新增：

- `surface`：`developer` 或 `executive`；
- `publication_id`：管理对话必填，投影对话为空；
- `context_hash`：记录构建 Agent 上下文的摘要。

旧 Agent 类型只做历史读取映射，不再由新前端创建。

### 9.2 取消聊天交接

删除新界面中的“交接给下一位 Agent”：

- 企业投影 Agent 与管理决策 Agent 不共享对话；
- 投影发布就是正式交接；
- 管理 Agent 发现缺口时在回答中生成结构化缺口说明；
- 后续可把缺口汇总回开发者项目，但不把高管完整对话复制到投影 Agent 上下文。

### 9.3 管理上下文构建器

新增 `ExecutiveContextBuilder`，输入只能是 `publication_id`。它返回：

- 公司和项目摘要；
- 发布版本、发布时间和数据截止时间；
- 发布清单中的对象版本、关系版本、事件和指标；
- 已发布管理问题、因果资产和历史结果；
- 可向高管展示的来源引用；
- 明确的数据缺口和质量标志。

任何未进入发布清单的草稿、附件、导入样本和开发者对话都不能进入管理 Agent 上下文。

|---|---|
| 公司/项目选择和创建 | 移入开发者端 |

| 企业投影 Agent | 移入开发者端 |
| 管理决策 Agent | 移入高管端 |

| Agent 聊天交接 | 从新界面删除，由投影发布取代 |

## 11. 分阶段实施计划

### R0：冻结现状与契约

- 固定当前 111 项自动化测试；
- 保存麦数科技案例的公司、项目、答案、对象、关系和报告数量；
- 增加当前混合页面的浏览器基线；
- 冻结现有 API 调用清单和数据库迁移头。

出口：任何后续重构都能证明没有丢失项目数据。

### R1：发布领域模型

- 新增 publication 模型、Schema、Service 和 `0011` 迁移；
- 创建发布预览、校验、发布和读取 API；
- 为发布资源生成版本清单和摘要；
- 保证重复发布请求幂等；
- 保证发布后不可修改。

出口：开发者可以把一个通过校验的项目发布为高管可读取的不可变版本。

### R2：后端 Surface 拆分

- 新增 developer/executive 路由聚合器；
- 增加 `EIP_SURFACE` 和应用装配测试；
- executive 模式不挂载公司/项目创建和投影写路由；
- 保留旧 `/api/v2` 兼容代理并记录调用。

出口：仅启动 executive surface 时，写接口在 OpenAPI 和实际路由中都不存在。

### R3：开发者前端

- 将当前 V2 页面迁移为 `static_developer`；
- 删除管理决策 Agent 标签和聊天交接；
- 重排为七阶段开发流程；
- 新增投影版本差异、发布校验、发布和高管端预览；
- 保留公司/项目创建、导入、建模、映射、审批、密钥和诊断。

出口：开发者能从新建公司走到发布版本，且无需进入高管端完成项目建设。

### R4：高管前端

- 建立独立 `static_executive`；
- 只展示已发布项目、版本状态、管理 Agent、来源和对话历史；
- 只有一个项目时自动进入；
- 支持新建、重命名、删除和恢复管理对话；
- 不加载开发者端 JavaScript 和表单。

出口：高管无需理解本体、数据映射、提案和项目阶段即可开始查询。

### R5：Agent 上下文硬隔离

- 管理线程绑定 publication；
- 实现 `ExecutiveContextBuilder`；
- 管理 Agent 回复记录 publication、上下文摘要、来源和模型信息；
- 删除新前端的跨 Agent 交接；
- 投影 Agent 保持草稿项目上下文。

出口：修改开发草稿不会改变既有高管对话的回答上下文。

### R6：真实流程验收与清理

- 用麦数科技从开发者端重新走完整流程；
- 发布一个管理层版本；
- 在高管端执行典型查询、证据展开和历史对话操作；
- 测试多个公司、多个项目和多个发布版本；
- 删除旧混合前端、混合 Agent 标签和无调用兼容代码；
- 更新桌面快捷方式和使用手册。

出口：产品、文档、测试和实际页面只表达开发者—发布版本—高管查询这一条主链。

## 12. 必须通过的验收场景

### 场景 A：开发者完成项目

1. 创建公司和项目；
2. 导入问卷答案 CSV 和三份调研报告；
3. 使用企业投影 Agent 提取并确认候选；
4. 建立对象、关系、事件、指标和系统映射；
5. 解决发布阻断项；
6. 预览发布清单；
7. 发布版本 1；
8. 在高管预览中验证可查询内容。

### 场景 B：高管查询

1. 高管端只看到已经发布的项目；
2. 新建管理对话；
3. 询问“当前最值得关注的问题是什么”；
4. 回答显示版本号、数据日期、事实、推断和来源；
5. 点击来源能查看对应发布资源；
6. 删除对话不删除项目或发布版本。

### 场景 C：草稿隔离

1. 开发者发布版本 1；
2. 高管在版本 1 建立对话；
3. 开发者修改草稿但不发布；
4. 高管继续提问时仍只读取版本 1；
5. 开发者发布版本 2；
6. 旧对话保持版本 1，新对话可选择版本 2。

### 场景 D：能力边界

1. executive surface 的 OpenAPI 不存在公司和项目创建端点；
2. executive 页面不存在导入、本体、映射、提案、密钥和诊断控件；
3. 管理 Agent 无法调用投影写工具；
4. 企业投影 Agent 无法读取高管私人对话；
5. 任意管理回答都能说明使用了哪个 publication。

### 场景 E：多公司和多项目

1. 开发者创建至少三家公司，每家公司至少两个项目；
2. 只发布其中部分项目；
3. 高管端只显示已交付项目；
4. 项目切换后对话和来源不串项目；
5. 同名对象在不同公司仍保持隔离。

## 13. 非目标

- 本轮不拆微服务；
- 不复制两套企业数据库；
- 不把外部问卷系统合并进 Palantir；
- 不让高管维护公司和项目；
- 不让管理 Agent 直接执行决策和行动；
- 不用前端隐藏代替运行时路由边界；
- 不在同一个 JavaScript 文件中长期维护两套界面；
- 不因拆分前端而删除现有真实企业项目数据。

## 14. 完成定义

只有同时满足以下条件，拆分才算完成：

- 公司和项目只能从开发者平台创建和维护；
- 企业投影 Agent 只出现在开发者平台；
- 管理决策 Agent 只出现在高管使用者平台；
- 高管只能进入已发布项目；
- 每个管理对话绑定不可变发布版本；
- executive runtime 不挂载开发者写 API；
- 两端前端代码和导航独立；
- 麦数科技和多公司合成案例均通过端到端测试；
- 全量自动化测试、迁移检查、OpenAPI 边界检查和浏览器测试全部通过；
- 文档和桌面启动入口与实际产品一致。
