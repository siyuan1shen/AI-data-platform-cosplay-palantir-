# 重构实施记录（2026-09-16）

本文记录 41 号统一重构方案已经落到代码的部分，避免把设计方案误当成完成证明。

## 已完成

- 新公司创建后自动拥有一份统一企业投影；前端只选择公司，投影键仅在兼容旧接口和内部服务时使用。
- 默认使用一个 SQLite 物理数据库。正式企业模型、管理观察、潜在认识、系统接入、情景运行和控制记录仍由不同逻辑表与服务维护，不能因为共库而互相提升可信度。
- 情景运行使用类型化流量平衡规则，不执行 `eval`、模型生成脚本或任意 SQL。每次运行冻结输入、规则、企业修订、状态和结果。
- 管理 Agent 的 Action 目录新增 `run_scenario_simulation`，完整经过创建、预演、执行、运行记录和幂等重试；推演结果不修改正式投影或外部系统。
- 管理端增加情景推演卡片，可创建情景、输入基线/事件后的周期需求与产能、执行计算并看到完成量和期末积压。
- 管理 Agent 增加公司级正式概览读取：公司整体查询不再要求伪造实体目标，仍通过注册 Action、范围校验和留痕执行。
- 运行时 OpenAPI 已重新生成，前端类型已同步；生产构建和前端单元测试均通过。
- 单库备份仍兼容现有备份服务，并能够读取逻辑域版本表；旧的分库实例仍可走显式分库配置。
- 情景推演补齐实物与服务两种流动语义：服务能力不跨周期结转，并拒绝非有限数字、重复周期及不兼容运行结果比较。
- 工作观察导入补齐包内事件去重、预览失效和切换公司清理；离线导出不再静默截断到前 1000 条，在线上传只有收到完整回执才清理本地缓存。
- 工作观察 Windows 默认采集改为应用级与粗粒度分类，不上传窗口标题；浏览器页面级识别保留给独立扩展，不把客户名称或文档内容默认带出终端。
- 建设端导航收敛为“企业 / 材料与企业建模 / 信息系统接入”，使用端收敛为“企业数字投影 / 管理 Agent”；旧管理输入和决策地址重定向到统一管理 Agent。
- 修复桌面启动：启动器不再误用 PATH 中的 Python 3.14，而是优先解析 Python 3.12；新增桌面友好的 CMD 包装器，并重建“企业数字投影平台”和“企业全面检查”两个快捷入口。

## 使用边界

推演只表示显式输入和已注册规则下的条件结果。管理层如果要把推演转为现实调整，应先查看规则、数据来源和未计算部分，再由建设流程建立正式变更草稿或由未来行业连接器执行真实动作。
