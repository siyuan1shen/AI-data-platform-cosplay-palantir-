# V3 使用手册

更新：2026-09-10。对应 `backend/`、`frontend/` 和 `/api/v3`。验证边界见[验收记录](32-v3-verification-report.md)。

## 启动与选择公司

最简单的方式是双击桌面的“企业数字投影平台”；你之前使用的“企业全面检查”也已恢复为兼容启动入口。若从项目目录启动，执行 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/launch.ps1`，等待 ready。建设端：`http://127.0.0.1:8012/developer/`；使用端：`http://127.0.0.1:8012/executive/`。停止服务用 `scripts/stop-v3.ps1`。

启动器不会把 PATH 中默认的 Python 版本当作唯一依据，会优先使用 Windows Python 启动器解析出的 Python 3.12；因此电脑同时安装 Python 3.14 时也可以正常启动。

验收或升级后，可运行 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/verify-v3.ps1 -RequireRuntime`，一次检查本地环境、后端回归、前端测试、类型检查和当前运行实例；`-SkipFrontendBuild` 只跳过重复构建，不跳过测试。

建设人员只需要创建或选择公司。系统会为公司自动建立唯一的“企业总体投影”，普通用户不再需要先创建或切换项目；旧的项目接口仍保留给历史数据和兼容测试。顶栏“使用端”进入正式发布视图，建设端的“材料与企业建模”页可以直接打开投影编辑器和发布区。

## 无系统数据：材料到企业投影

1. 创建公司。公司创建事务会同时建立唯一企业投影、默认本体和动作定义。
2. 在模型设置中输入自己的兼容模型地址、模型名称、密钥，测试后设为默认。MOCK 仅用于离线流程验收；其中订单履约建模是合成案例逻辑，其他行业现在也会按材料中明确出现的组织/流程词生成保守的起步草案，但不推断未被材料支持的职责、权限或潜在关系。
3. 在材料导入选择 Companycheck CSV、访谈 DOCX、文本 PDF、TXT/Markdown 等受支持文件。扫描图片 PDF 需要先转换为可提取文本。
4. 检查解析预览、字段映射和目标公司。Companycheck 的合并答案、问卷编号等列可识别；空答案跳过，重复回答合并。多公司文件须明确目标公司。
5. 确认导入，再检查文档和证据片段。预览不等于已导入；失败时修正映射重试，成功确认不能重复提交。
6. 新建企业投影 Agent 对话，选择材料并描述目标。例如：“建立组织、岗位、职责、权限与订单履约流程，注明来源、冲突与未知项。”调用外部模型时按页面选项确认发送范围。
7. 查看动作预演，需要审批的先批准再执行。检查实际状态；批量变更通过变更集原子写入，文字回复不等于已写入。
8. 如果是 Agent 产生的动作，人工执行完成后点击动作区的“继续 Agent”，让 Agent 回读工具结果并结束本轮；不要把“动作已成功”误认为整轮对话已经完成。
9. 在投影图点击对象或关系，查看属性与证据。可以手动编辑、调整参与方，或让 Agent 提出修订，再查看回读结果。
10. 填写版本名并正式发布；该操作同时冻结本体与投影。进入使用端核对公司和版本。未发布公司仍可在管理 Agent 中记录观察，但正式职责、金额和系统数据查询会明确提示尚无发布基线，不会把草稿冒充正式事实。

已经应用的变更集显示历史结果。后续草稿不自动改变旧发布；删除聊天不删除已经执行的建模结果。

如果材料超过初始上下文窗口，运行记录会显示每份材料的“已读/总片段”。Agent 可以通过按需读取工具继续读取指定材料的下一页；显示“部分读取”时，回复只能代表已读范围，不能当作完整材料结论。

大型企业投影不会要求一次性把整张图交给模型。Agent 会先按当前问题对对象、关系和材料片段排序，再按对象 ID 和关系深度调用图谱邻域读取；系统会优先保留关系邻居，并返回对象/关系总数、返回数和截断标记。出现截断时，Agent 必须继续缩小范围或分批读取。排序只是上下文选择，不会改变数据库中的事实顺序或正式图。

初始上下文默认最多包含 200 个对象和 400 条关系；可通过 `EI_BACKEND_AGENT_INITIAL_GRAPH_ENTITIES`、`EI_BACKEND_AGENT_INITIAL_GRAPH_RELATIONS` 调整上限。上限不是数据删除，完整数据仍保存在本地数据库中。

## 有系统数据：在同一模型上扩展

1. 建立文件数据源、本地 SQLite、通用 PostgreSQL 或通用 REST JSON 只读数据源。SQLite 配置填写 `{"database_path":"D:/data/erp.sqlite"}`；当前并非所有 ERP/MES 厂商都有现成插件，有 HTTP API 的系统可按响应路径、分页参数和游标配置 REST 连接器。
2. 预览资产、字段与样本。可以让系统本体 Agent 提出映射动作，也可以在“语义映射审核 → 字段候选助手（只读）”中选择数据源和目标本体类型，按字段名生成候选；候选只供人工复核，不会自动批准。确认无误后可以逐条点击“保存为草稿”，再在下方执行校验、批准，批准映射才会参与后续同步。
3. 先为稳定键、名称和属性建立字段映射，再在“来源关系映射”中填写外键字段、来源/目标本体类型、关系类型和两端角色。例如岗位表 `department_id` → `role.member` 到 `organization_unit.container`，必要时填写目标资产。
4. 检查身份键、单位转换、关系外键和 KPI 口径，分别校验并批准字段映射与关系映射；只有 APPROVED 才会参与下一次物化。
5. 确认预览批次。数据库确认使用已保存的提取结果，避免源数据变化导致前后不一致；系统会建立 `SYSTEM_BOUND` 关系并保留原始材料证据。
6. 处理未匹配身份、未知或不唯一外键、同权威来源冲突与设计/实际差异。同名不一定同物，不能仅凭相似名称覆盖；未知外键只进入物化运行的错误列表，不会自动猜测目标。
7. 映射修正后从原始批次重算；字段漂移需要重新检查。相同来源记录的系统关系使用稳定键更新，不会因为重算反复堆叠重复边。
8. 创建语义数据集，选择对象、关系和字段，查询导出给外部分析工具，并保留快照与来源。

系统观测不等于改写组织设计；资料缺失也不证明现实业务不存在。

## 管理目标到行动结果

1. 在使用端选择已发布项目，用图或管理 Agent 查询职责、流程和证据。
2. 提出目标，例如“减少交期反复，同时保留质量控制”，或使用“分析管理信号”快捷输入。
3. 查看洞察：只有设计信号是结构性预警；只有结果异常是待解释异常；双方支持仍需管理层判断，不能当成因果已证明。
4. 填写反馈并确认、驳回或持续监控。出现历史保留以前的判断和证据变化。
5. 在结果与确认区域回答信息请求、维护假设、会议和指标观测。Agent 自动动作完成后相关项目结果会刷新。
6. 让 Agent 提出不同方案，比较收益、代价、假设和替代解释。方案在隔离图上比较，批准后才应用到设计。
7. 人员实际实施组织调整，再记录效果、失败、副作用或暂无法判断，用可比期间的 KPI 复查。
8. 从行动结果生成案例草稿并检查适用条件。另一企业可显式参考案例，不能把案例事实直接复制成自身事实。

## 保存、交换和恢复

本地数据默认位于 `%LOCALAPPDATA%\EnterpriseInsight\data`，不在代码仓库。勿把真实资料、导出或数据库副本放进代码、文档、测试目录再提交。

项目包用于离线传输和恢复：先恢复预览校验，再确认恢复。包内剔除模型和连接器密钥，恢复后重新配置。CSV/XLSX 便于分析，但不能替代保留引用与历史的项目恢复包。

SQLite 旧版本升级前会在数据库旁的 `schema-backups/` 创建一致性备份，包含已提交的 WAL 数据；已经是当前版本的正常启动不重复备份。升级失败会报告备份位置并停止启动。保留该文件和错误日志，停止服务后再安排恢复，勿删除旧库或重复覆盖备份。此机制只覆盖本地 SQLite，外部数据库应使用对应数据库的备份流程。

开发者还可以通过评测集的“执行评测”按钮，让每个有效案例实际创建独立 Agent 对话并运行，再由系统从持久化结果消息、动作日志和可验证引用评分。Worker 开启时按钮提交持久化异步执行任务，页面自动轮询并显示完成/失败状态；Worker 关闭时由同一接口在请求内完成。完成后“最近一次运行结果”会显示通过数、平均分、每个案例的动作、引用数和 Agent 输出。这个入口不会接受调用方自报的 citation 数或 action 列表作为真实运行结果；外部模型必须显式允许外发并记录模型配置。当前本地示例使用 MOCK，只验证运行与评分链路，不代表真实模型质量。旧的同步 `/runs` 接口仅保留给明确关闭 Worker 的服务端调用，建设端不再要求用户手动切换运行模式。

## 常见问题

- 旧页面：等待启动器构建完成，再刷新 8012；健康接口可核对 build ID。
- 校验失败：检查映射及错误字段，勿靠增加无意义字符绕过。
- Agent 没写入：检查待审批、预算暂停或执行失败状态。
- 完整上下文超限：本轮不会发送残缺内容。增加 `EI_BACKEND_AGENT_CONTEXT_MAX_CHARS` 后重启再继续，或缩小任务范围；只点“继续”不会自动扩大上下文预算。外部模型遇到 408/429/5xx 或传输超时会按 `EI_BACKEND_AGENT_MODEL_MAX_RETRIES` 有限退避重试，认证、权限和地址错误不会盲目重试。
- 看不到模型：确认公司、项目及草稿/正式版本。
- 分析无洞察：检查分析记录与信号数量，可能需要补充结构或现实观察。
- 外部调用失败：先测试模型配置。MOCK 成功不能证明外部模型连接及工具调用成功。
