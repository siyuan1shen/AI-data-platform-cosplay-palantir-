## 2026-09-13 潜在候选人审、图编辑和跨库确认

- 控制库可从正式 AgentRun/AgentStep 的候选 outbox 幂等建立 `PROPOSED` 候选；正式/观察事实不会因候选而被写回或提级。
- 候选支持项目内分页、详情、历史、带预期哈希的修改/拒绝/确认；修改不得替换已验证的证据或提高证据状态。版本、操作者、决定、内容摘要和快照写入不可改写事件。
- 接受流程先在控制库提交 `ACCEPTING`/`RECEIVED`，再用 candidate/version/hash 派生幂等键写入潜在库，最后记录 `COMMITTED` 回执并关联正式潜在记录；进程在两库之间中断时可安全重试，不产生重复潜在记录。接受记录仍可保持 `UNTESTED`，人工接受不等于证据已验证。
- 管理输出 Agent 现在仅在 `COMPLEX_ANALYSIS` 运行可提交候选提案；字段需匹配公司/项目，至少一条支持证据，支持与反证必须引用同一项目内当前有效的精确观察版本并包含逐字摘录。伪造、越界、旧版本、无逐字证据均只记安全拒绝原因码/计数，分析回答照常返回，候选不会写入潜在库。
- 人工确认前如果来源已被修订/撤回，API 会把候选记为 `STALE` 并阻止入潜在库；已进入 `ACCEPTING` 的跨库恢复则继续使用已绑定的候选快照和幂等键，避免源变化导致已提交操作无法回执。
- 候选的人审前端暂未接线；本轮 Agent 输出测试使用模拟模型结果，尚无真实模型密钥下的真实模型质量评估。

## 2026-09-13 工具读取来源进入结论追踪

- 不复制搜索词、观察内容、潜在判断或访谈正文；覆盖清单只记录扫描元数据与成功返回的来源引用数量。引用有效仍只证明本轮读过该来源，不证明其语义支持结论或因果关系。
