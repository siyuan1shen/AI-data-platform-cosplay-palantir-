# 独立工作观察模块

## 使用顺序

1. 管理员在建设端创建公司和项目，并完成企业投影的岗位、流程和人员标识。
2. 在员工电脑上单独运行 `backend/scripts/independent_work_collector.py`。员工不需要安装或登录管理平台。
3. 采集器将活动保存在本地 SQLite 缓存中：可以在线批量上传，也可以导出 JSON 离线包。
4. 在使用端的“企业数字投影 → 岗位工作观察”中导入 JSON，先预览，再确认导入。
5. 如果需要把来源员工解释为正式企业对象，在同一页面配置来源身份绑定；绑定前的数据只显示为来源标识。
6. 点击“生成分析”，查看岗位工作片段、相邻路径和员工之间的描述性差异。
7. 如需补充岗位虚模，点击“生成活动候选”，逐条确认或拒绝；确认只写入岗位虚模草稿，仍需在虚模页面审核发布。
8. 管理 Agent 可以通过 `work_observation.read` 和 `work_observation.compare` 读取已经完成的分析。

## 数据边界

工作观察保存在独立观察库，不会自动修改正式企业投影、岗位职责、权限或绩效。所有路径只表达“观察到的时间先后”，不能直接解释为绩效、最佳流程或因果关系。系统不接受键盘内容、鼠标点击、截图、录像、密码和完整 URL 参数。

在线上传成功后才清理本地缓存；失败会保留缓存，便于重试。离线导入和在线上传使用相同的数据包格式、批次摘要和事件去重规则。导入预览会展示样例事件、时间范围、状态分布、重复/冲突数量和身份绑定警告。来源身份绑定支持解绑、重新绑定，并保留每一次人工变更历史。

## 管理 Agent 的读取边界

- 简单任务不主动读取工作观察库。
- 复杂任务可以读取工作观察分析，但输出必须标明这是独立采集的描述性证据。
- 观察数据只能通过已注册动作读取，Agent 不能执行任意 SQL，也不能直接写正式企业库。
- 采集事件按项目、设备、会话和不透明员工标识隔离；员工端提供的名称不作为正式身份依据。身份绑定由平台校验正式企业对象属于当前项目后保存，重复或冲突绑定不会静默覆盖。
- 复杂管理任务会在发布版本范围内读取已审核岗位虚模；虚模内容仍带有审核状态和来源，不会升级为正式事实。工作观察候选确认后只形成虚模草稿，只有人工审核记录后管理 Agent 才能读取为已审核岗位设计上下文。

## 当前采集器交付

采集器以独立 Python 脚本和 Windows 打包脚本交付，支持 Windows 前台窗口、空闲/锁屏状态、本地 SQLite 缓存、在线批量上传和离线 JSON 包。运行 `backend/scripts/build_collector.ps1` 可生成无 Python 依赖的 exe；浏览器扩展和企业级自动升级仍属于后续增强。它不需要员工登录管理平台，也不采集键盘、鼠标、截图或录像。
