# 平台规划总纲（历史版本）

> 本文已停止作为现行规划。当前权威产品定位、架构、流程和建设顺序统一见[管理层企业决策投影总体规划](13-executive-decision-platform.md)及[端到端业务流程](14-end-to-end-workflows.md)。本文仅用于解释早期代码和 Edge—Hub 设计来源，不得据此增加安全治理、交换协议或生产化工作。

> 早期版本曾采用“分部边缘终端 → 总部中心枢纽”拓扑，相关档案见[已冻结的分部边缘终端—总部数据飞轮架构](11-edge-hub-flywheel.md)。它不再约束新产品设计。

## 1. 使命

将各分部散落在问卷、访谈、文档和业务系统中的信息安全汇聚到总部，转化为一张可验证、可追溯、可解释的企业语义图；让人能够轻松理解企业，让 Agent 能够可靠分析企业，让总部数据飞轮持续改进问题、本体、映射、程序和诊断能力，并在独立治理后形成可共享行业资产。

## 2. 最终能力

平台应稳定回答：

1. 企业由哪些组织、人员角色、产品、客户、供应商、流程、系统和指标构成？
2. 从获客、接单、生产、交付到回款的价值流如何运转？
3. 同一个客户、物料或订单在不同系统中分别叫什么？
4. 哪些字段、编码、枚举、单位和业务口径不一致？
5. 哪些信息是事实、受访者陈述、推断、冲突或未知？
6. 当前主要风险、根因和改进建议是什么？
7. 每个结论的来源证据和数据血缘在哪里？
8. 整改是否执行，执行后是否真正改善？

## 3. 可验收红线

“不得出现冲突”被工程化为以下可验收目标：

- 零静默冲突；
- 零破坏性覆盖；
- 零不可逆实体合并；
- 零未版本化正式资产；
- 零未经审核的 Agent 正式写入；
- 零无证据高风险 Finding；
- 零跨租户原始数据检索；
- 零总部直连分部数据库；
- 零未签名、未加密或未留回执的跨边界导入；
- 零因重复或乱序数据包产生的重复正式事实。

源系统之间可以存在真实冲突，但平台必须发现、隔离、解释、审核并可逆处理。

## 4. 平台平面

### 4.1 企业私域数据平面

分部 Edge 保存本地原始回答、附件、来源记录和必要的私有分析；总部 Hub 保存经显式导出的集团数据、统一事实、报告和整改结果。数据默认不离开企业集团边界，分部到总部的移动不自动获得跨企业共享权。

### 4.2 数据交换平面

负责分部 Enrollment、导出预览、全量/增量/更正 Bundle、签名加密、在线断点续传、离线拷贝、总部隔离导入、幂等、回执和签名发布包。在线与离线传输共用同一协议，禁止数据库复制和双向表同步。

### 4.3 语义集成平面

负责 Source Schema、字段映射、值映射、单位转换、实体解析、本体对齐、数据血缘、质量检测和冲突中心。它是所有 Agent 的知识底座。

### 4.4 Agent 运行平面

由确定性 Workflow Orchestrator 控制专业 Agent。Agent 只读取授权上下文并产生结构化提案，不能直接写正式知识。

### 4.5 企业解读平面

提供企业全景、价值链、系统图、数据流、风险图、证据视图、自然语言查询、报告和整改看板。

### 4.6 可信发布平面

处理行业贡献候选的用途授权、DLP、脱敏、罕见组合检测、人工审核、评测、签名、发布和撤回。

### 4.7 行业共享平面

保存版本化 QuestionPack、Ontology、FindingPattern、Mapping Program、Agent Recipe、Diagnostic Playbook、Eval Suite 和聚合质量指标；不保存默认企业原始 Workspace。

### 4.8 横向控制平面

统一处理身份权限、租户策略、密钥、模型路由、运行预算、审计、版本、发布门禁、回滚、备份和灾难恢复。

## 5. 核心业务闭环

```text
分部数据接入
→ 证据化
→ 签名加密 Bundle
→ 总部隔离、校验和幂等导入
→ 语义映射与实体解析
→ 集团统一知识图
→ Agent 提案
→ 人工审核
→ 正式 Finding/报告/本体
→ 整改和结果复查
→ 总部知识版本回流分部
→ 获独立跨企业授权的资产候选
→ 脱敏、评测、行业发布
→ 下一家企业复用
```

## 6. 技术战略

### 6.1 先模块化单体

首个生产版本使用 FastAPI、Pydantic、SQLAlchemy、Alembic 和明确的模块接口。模块可以在同一进程运行，但不能跨边界直接操作对方表。

### 6.2 后续部署形态

- Edge Local：分部单机、SQLite、本地文件、BYOK、回环监听和隐式 Local Owner；
- Edge Team：分部小型内网服务、本地账户或 OIDC、分部内审核；
- HQ Hub：总部内网/私有云、PostgreSQL、对象存储、OIDC/SSO、RBAC/ABAC、Worker 和集中飞轮；
- Industry Registry：与总部企业私域分离的跨企业资产注册表和联邦评测控制面。

`environment` 表示 local/test/staging/production，`deployment_profile` 表示 edge_local/edge_team/hq_hub，两者不得相互代替。

### 6.3 演进标准

只有出现独立伸缩、安全边界或团队所有权需求时才拆服务。技术先进性不以服务数量、Agent 数量或 token 消耗衡量。

## 7. 北极星指标

```text
Verified Insight Yield
= 有证据、审核通过、后续有效的 Finding 数 / 顾问审核小时
```

```text
Flywheel Lift
= Quality(新知识版本, 固定模型, 固定评测集)
  - Quality(旧知识版本, 同一模型, 同一评测集)
```

## 8. 项目建设顺序

1. Edge/HQ 运行档位、公共契约和设备身份；
2. 离线 Bundle、总部收件箱、回执和增量游标；
3. 在线断点续传与可靠 Outbox；
4. Source Catalog、Canonical Entity、Fact 和冲突中心；
5. 总部受控多 Agent、企业解读和整改结果；
6. 总部 Ontology、Program、QuestionPack 和评测飞轮；
7. 签名 Release 回流分部；
8. 独立治理的跨企业行业共享；
9. 企业级安全、容量和高可用。

## 9. 不在第一阶段做

- 全局企业原始数据向量库；
- Agent 点对点自由群聊；
- 动态无限规划；
- Agent 生成任意代码并执行；
- 自动在线训练；
- 大规模微服务化；
- 总部直连分部数据库或复制 SQLite 文件；
- 为在线上传和线下拷贝维护两套业务格式；
- 在真值层使用万能 EAV 取代清晰领域模型。
