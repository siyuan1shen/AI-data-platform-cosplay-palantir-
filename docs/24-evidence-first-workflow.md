# 24 证据优先工作流决议

本文档是当前产品流程顺序的最高优先级约束。它解决一个核心问题：管理层最初提出的关注方向不能直接当成已经验证的管理问题；系统必须先形成可追溯的企业数字投影，再进入正式诊断、因果分析和行动闭环。

## 一、唯一推荐顺序

1. **公司与项目**：选择公司和项目，填写项目范围、初始关切、负责人和目标日期。初始关切只是调研起点，不是事实，也不是正式管理问题。
2. **材料与调研**：通过 Agent 对话、问卷导入、访谈记录和现场材料建立调研批次、问题、回答、发现和证据。
3. **上游企业设计**：把材料中的组织、岗位、能力、流程、信息流和资金流建模，并记录岗位职责、流程衡量方式和代理风险。
4. **发布设计基线**：冻结一版企业“应该如何运转”的不可变设计快照。没有系统数据的企业在这里即可交付管理层查询。
5. **下游数据接入（可选）**：只有需要用 ERP、MES、CRM、财务等实际数据校准时，才创建绑定设计基线的运行投影，记录来源、映射、导入批次和观察值。
6. **投影校验**：系统分别检查上游设计是否可解释、下游运行数据是否可用；没有下游数据不是设计层失败。
7. **管理诊断**：只有投影校验通过且项目进入分析阶段后，才能创建正式管理问题；问题必须绑定发现、证据或投影中的对象关系。
8. **因果、决策与行动**：对正式问题建立因果假设、情景、决策和行动，保留假设、依据与预期结果。
9. **执行结果与学习**：录入行动结果和新证据，回写本体、映射、因果假设和 Agent 评测数据。
10. **管理报告**：从上述版本化数据生成可追溯报告；报告是当前投影的不可变快照，不反向修改事实。

## 二、两个容易混淆的入口

### 初始关切

在“公司与项目”中填写，用于告诉调研 Agent 从哪里开始。例如“交付周期可能影响续约”。它可以很模糊，可以在调研中被证伪，也不要求此时已有证据。

### 正式管理问题

在“管理诊断”中创建，用于推动后续因果、决策和行动。例如“交付延期的主要约束是否集中在排产与质量放行之间”。它必须在投影校验通过后创建，并以候选或已确认状态管理。

## 三、Agent 的位置

Agent 按模块分工，但不改变流程门槛：

- 调研 Agent：把人的叙述整理为问题、回答、发现和待核实项。
- 本体 Agent：提出对象、类型、属性、关系和映射候选。
- 数据接入能力：解释文件结构、建议字段映射和发现异常；只有创建运行投影后才执行下游写入。
- 投影校验 Agent：解释缺失项、冲突项和下一步补充建议。
- 诊断 Agent：在正式诊断阶段提出问题候选，并引用证据。
- 因果/决策/行动 Agent：提出假设、情景、决策和行动草案。
- 报告 Agent：根据已确认的数据生成管理层可读的解释。

Agent 工作台是跨阶段的对话入口；审核收件箱是全局的候选项处理入口。两者都不能绕过正式阶段门槛，也不能把提案直接写成已确认事实。

## 四、允许的回环

主流程是单向推进，但真实调研必须允许受控回环：

- 新回答可以补充或修订本体候选；
- 新对象可以触发关系和数据映射补充；
- 投影校验失败时回到调研、本体或数据接入；
- 新证据可以使正式问题降级、归档或重新打开；
- 行动结果可以更新因果假设，但不覆盖历史报告快照。

回环必须留下修订版本和来源，不能通过覆盖旧记录消除历史。

## 五、代码中的落点

- 项目初始关切：`project_briefs`，接口 `GET/PUT /projects/{project_id}/brief`。
- 正式管理问题：`management_issues`，接口 `GET/POST /projects/{project_id}/management-issues` 和 `PATCH /projects/{project_id}/management-issues/{issue_id}`。
- 投影校验：`GET /projects/{project_id}/projection-readiness`，前端“投影校验”页面展示阻断项。
- 旧 `charter` 和 `decision_questions` 接口保留用于兼容历史数据，但新流程不再把它们作为前置正式诊断入口。

## 六、完成定义

一个项目只有同时满足以下条件，才算完成“可解释企业”的第一阶段：

- 能说明调研范围和初始关切；
- 有可追溯的调研、回答、发现和证据；
- 有已确认的企业设计节点和必要关系，并发布设计基线；
- 若项目声明接入系统，则有已确认的运行数据来源或业务观察；未接入系统的项目不要求这一项；
- 对应层级的投影校验通过；
- 正式管理问题能够引用投影中的证据；
- 后续决策、行动、结果和报告都保留版本与来源。
