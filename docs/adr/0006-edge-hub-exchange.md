# ADR-0006：分部 Edge 与总部 Hub 使用统一交换包

- 状态：Superseded by [ADR-0007](0007-executive-decision-projection-focus.md)
- 日期：2026-08-24

## 背景

> 2026-08-29 更新：统一交换包实现可保留为兼容能力，但不再决定产品架构和建设优先级。

当前 V1 是单实例本地平台，统一要求账号 Bootstrap，并只提供问卷 JSON/CSV 导出和本地飞轮注册中心。目标组织需要多个分部方便交付数据：有网络时在线上传，无网络或隔离网络时通过 U 盘、移动硬盘等线下拷贝；数据应在总部统一治理并驱动飞轮。

如果在线同步、离线文件和总部导入分别实现，会产生格式漂移、重复数据、不可对账和不同安全结论。若总部直接连接分部数据库，则会把网络、Schema、权限和故障耦合到一起，也无法支持隔离网络。

## 决议

1. 使用同一套代码提供 `edge_local`、`edge_team` 和 `hq_hub` 三个 Composition Profile，不维护分叉项目。
2. 分部与总部不共享数据库。所有跨边界业务数据通过不可变 `EIP Exchange Bundle`、Receipt 和 Release 交换。
3. 在线上传和离线拷贝移动相同的 Header、加密 Chunk 和签名；两者调用相同 Validator 与 Importer。
4. Bundle 遵循 `EIP-XP/1`，使用分部设备密钥签名、标准 HPKE 与总部接收公钥加密、逐块哈希、全局 Bundle ID、增量序列和前序哈希。
5. 总部从已登记 EdgeNode 公钥解析真实 Tenant 与 OrganizationUnit，不信任 Bundle 自报的身份作为授权依据。
6. 总部导入先进入隔离区和 Raw Landing，通过安全、契约、幂等、DLP 和人工门禁后才进入语义与业务层。
7. `edge_local` 在回环地址和单操作系统用户边界下使用隐式 Local Owner，不强制账号密码；`hq_hub` 必须强认证、RBAC/ABAC 和审计。
8. 分部到总部属于同一企业 Tenant 内的数据传输。跨企业行业共享是独立流程、存储和授权域。
9. 总部产生的 QuestionPack、Ontology、Mapping Program、Agent Recipe、Playbook 和策略以签名 Release 回流分部，先兼容检查和 Shadow Eval，再人工启用。
10. 缺少前序增量的包可安全收件但不能提交可信数据层；V1 只允许整包事务提交，不允许静默部分导入。

详细协议、状态机和验收标准见[分部边缘终端—总部数据飞轮总体架构](../11-edge-hub-flywheel.md)。

## 后果

### 正面

- 分部可完全离线工作；
- 在线和离线具有相同完整性、幂等、导入结果和审计语义；
- 总部无需暴露或连接分部数据库；
- 总部飞轮获得稳定、可追溯的多分部输入；
- Edge 与 Hub 复用领域契约和可靠性内核；
- 本地单机体验与总部多人安全不再互相妥协。

### 代价

- 需要设备登记、密钥生命周期、隔离区、回执和 Schema 兼容治理；
- 总部结果不是实时数据库镜像，而是以已确认 Bundle 为数据完整性边界；
- 更正、撤回和缺包必须显式建模；
- 大型 Bundle 需要流式打包、分块和容量治理。

## 被拒绝方案

- **复制 SQLite 或共享数据库目录**：无法安全并发、难以版本化和对账，也不能支持不可信介质；
- **总部直接查询分部 API/数据库**：要求持续联网并扩大攻击面，故障和 Schema 高耦合；
- **在线 JSON API + 离线 ZIP 两套格式**：长期必然产生验证和业务结果漂移；
- **所有分部自动实时上传**：违反本地数据主权、隔离网络和显式授权要求；
- **用用户账号代表设备**：人员与设备生命周期不同，不能提供稳定来源签名；
- **分部数据到总部后自动进入行业共享**：混淆企业内部用途和跨企业授权。
