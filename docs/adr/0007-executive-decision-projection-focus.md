# ADR-0007：聚焦管理层企业决策投影

- 状态：Accepted
- 日期：2026-08-29
- 取代：[ADR-0006](0006-edge-hub-exchange.md)作为产品主架构的地位

## 背景

旧 V1 同时建设了问卷、Evidence、语义映射、Agent、报告、安全治理、分部—总部交换和行业飞轮，范围远超当前团队能够用真实业务验证的边界。结果是系统有大量横向模块，却缺少决定产品价值的数字投影内核：实体关系边、图查询、事件、指标、时间投影、完整数据血缘、可执行 Agent、因果分析和行动结果学习。

当前真实切入方式不是替大型企业完成整体信息化，而是服务核心管理层：先通过问卷、访谈和实地调研形成最小企业模型，再按管理问题逐步接入已有系统的数据。

## 决议

1. 产品定位为“管理层企业决策投影平台”，不替代 ERP、CRM、MES、OA 或财务系统。
2. 唯一主流程为：项目定义 → 管理层调研 → 现场证据 → 初始数字投影 → 高价值系统接入 → 分析与因果 → 决策 → 行动 → 结果 → 学习。
3. 数字投影必须原生表达 Object、Link、Event、Metric、Action 和 Causal Model；旧 `Fact` 只作为迁移兼容层。
4. Agent 必须通过本体、图、时间、指标、因果和行动工具工作，并持久化运行过程；不再以固定文本配方数量代表能力。
5. 企业内部飞轮以行动结果为主要学习信号；相似企业经验只能作为可解释先验，通过目标企业试点验证后才能采纳。
6. 当前资源集中于本体图、数字投影、数据接入血缘、Agent 工具、因果行动和同行学习。
7. 安全治理、复杂多租户、加密交换、云端高可用、扩展沙箱和微服务化从当前产品模块及交付路线移除，资源分配为零。
8. 现有身份、凭据、本地边界和 Edge—Hub 代码不主动拆除，以免破坏可运行原型；除阻断本地使用的缺陷外不再扩展。
9. 分部数据确需汇总时，当前优先使用简单文件导出、线下拷贝或普通上传；统一加密交换协议仅作为冻结兼容能力。
10. 新功能必须同时提供领域模型、数据库、API、前端操作、示例数据、测试和端到端演示。

## 后果

### 正面

- 产品围绕管理层可理解、可决策、可验证的闭环，而不是堆叠基础设施；
- 调研信息可以逐步演进成真实企业关系图，不要求先完成全企业信息化；
- 每个系统接入都有明确管理问题和预期价值；
- Agent、因果和数据飞轮有统一的数据基础及结果反馈；
- 团队能够通过一个纵向场景验证产品，而不是同时维护多条未闭环路线。

### 代价

- 旧安全治理和 Edge—Hub 代码会暂时存在但不继续完善；
- 当前版本不宣称是企业级云生产平台；
- 必须重构旧 `Entity`、`Fact`、`AgentRun`、`Action` 和 Flywheel 模型；
- 行业飞轮必须等至少两个企业项目产生可比较结果后才能证明。

## 首个验证场景

固定使用制造企业“客户—订单—生产—交付—开票—回款”。第一阶段必须完成跨来源对象关系图、事件指标、一个原因假设、一个行动及其结果复盘。
