# Enterprise Insight 使用手册

## 一、产品定位

外部问卷系统负责问卷设计、填写、追问和原始答案采集；V3 开发者平台负责企业边界、投影 Agent、对象关系、时间投影、系统数据接入、因果决策、行动学习和发布。高管平台只消费已经冻结的发布版本，并通过管理决策 Agent 查询。

当前推荐流程是：在任意问卷系统完成问卷后导出标准 CSV，再在 Palantir 导入。两套系统不共享数据库，也不会互相改写运行目录。

## 二、首次启动

1. 双击桌面“Enterprise Insight 一键启动”。
2. 本地模式会自动创建本机数据目录和本地所有者，不需要输入账号密码。
3. 如果浏览器没有自动打开，访问启动脚本提示的本地地址。
4. 启动器会打开开发者平台（`/developer/`，根路径 `/` 也指向它）。先创建公司，再创建“解读项目”；公司和项目是分开的两个选择器。
5. 高管平台位于 `/executive/`。新项目在开发者发布前不会出现在这里。

V3 本地模式不需要平台账号或租户密码。代码在 Git 仓库中，数据库、密钥和附件位于仓库外的本机实例目录，不会因提交代码而自动上传。旧 V1/V2 API、旧界面和旧迁移链已关闭，不再作为运行入口。

## 三、推荐使用流程

左侧先分别选择“当前公司”和“当前项目”。公司是长期企业边界；项目是一次独立解读、诊断或改进过程。同一家公司可以有多个项目，项目之间不混用上下文。

1. 在“公司与项目”创建公司、项目，写清范围和初始关注方向；不要在此填写正式诊断结论。模型配置也在这个设置页完成。
2. 在“材料与调研”导入问卷答案 CSV；访谈总结、现场记录也可以作为 Agent 附件上传。
3. 在“上游：企业设计”完善组织、岗位、能力、流程、信息流和资金流等设计投影；并补充岗位职责为什么这样设计、流程哪些部分可量化以及可能产生什么代理问题。也可以把材料直接交给企业投影 Agent。
4. 在同一页面点击“发布设计基线”。这一步冻结企业应该如何运转的版本；没有 ERP/CRM 也可以完成，并可供管理层查询。
5. 只有确实有系统数据时，进入“下游：系统数据（可选）”，创建运行数据投影（例如 ERP 订单运行投影）。之后再到“本体与上下游对齐”建立本体概念、绑定设计、确认系统字段映射和跨系统身份。
6. 下游运行投影创建后，导入 CRM、ERP 等 CSV，先预览字段与映射，再确认生成运行对象、关系、事件和指标，并保留血缘。
7. 在“校验与发布”分别查看设计层和运行层状态。运行层未接入时不是错误，管理层查询会明确只基于设计层证据。
8. 发布通过后，在“企业投影 Agent”中继续补充投影或查询材料；所有结构化写入都必须经过人工确认。
9. 在“校验与发布”填写版本说明并发布不可变投影。
10. 管理层打开高管平台，选择项目和发布版本，再向管理决策 Agent 提问。

“企业投影 Agent”是建模协作入口，不是必须首先完成的业务阶段；投影创建、对齐和发布仍由开发者确认。

## 四、开发者与高管两类平台

平台只保留两个用户可见的主 Agent，但不把它们放在同一个工作台：

1. 企业投影 Agent 只在开发者平台，服务 FDE、调研者和建模人员。可以上传 `txt`、`md`、`csv`、`json`、`docx` 或 `xlsx` 材料，整理投影草稿并形成待确认提案。
2. 管理决策 Agent 只在高管平台。它不能创建公司、项目或模型，也不能修改投影，只能读取当前选择的发布版本。
3. 两个 Agent 不使用聊天“交接”。正式边界是一次不可变发布：项目、清单、版本、哈希和发布时间都被固定。
4. 高管每段对话固定绑定一个发布版本。开发者发布新版后，旧对话仍继续依据旧版回答；需要使用新版时新建对话。
5. 两类对话都可以删除；删除对话不会删除正式投影或发布版本。

Agent 的自然语言回答不是正式事实。需要落库的对象、关系、发现、因果假设、决策或行动计划，应形成结构化提案，再由人批准和执行。

## 五、可选模型与密钥

在“模型与密钥”中可以创建 OpenAI、DeepSeek、OpenAI-compatible 或 Mock 配置，并测试连接。密钥保存在本机加密存储中，接口和页面不会回显完整密钥。

开发者 Agent 每次发送消息时，只有主动勾选“使用已配置的默认模型处理本次输入”，才会调用外部模型。高管管理 Agent 在有默认模型时自动发送“当前问题 + 当前固定发布快照”，没有模型配置时使用本地确定性回答；它不会发送开发者草稿、其他项目或其他发布版本。

## 六、问卷数据进入 Palantir

1. 在所用问卷系统的管理页面导出答案 CSV。
2. 保存导出的 CSV 文件；不要把文件复制到 Git 仓库的代码目录。
3. 在 V3 选择公司和解读项目。
4. 在“导入问卷与调研答案”选择 CSV，点击“读取并预览”。
5. 检查有效答案、空答案和合并重复数量，再点击“确认导入”。

导入会保留公司标识、问卷编号、检查维度、问题编号、问题类型、问题文本和合并答案。空答案不导入；同一公司、同一问卷、同一问题、同一访谈视角的多条答案合并保存。不同访谈视角不会互相覆盖：如果 CSV 额外提供“访谈视角”（也兼容“受访者角色”“角色”“视角”），总经理、销售、财务等观点会分别展示和导出。没有角色列的旧版问卷答案 CSV 仍可正常导入。

只有点击“确认导入”才会写入项目，预览不会落库。

## 七、从答案建立企业投影

1. 在“上游：企业设计”描述企业应该如何运转，例如销售岗位、订单流程、交付流程和回款流程。
2. 点击“发布设计基线”，把这一版设计冻结下来。
3. 如果有系统数据，在“本体与上下游对齐”创建稳定概念，例如 `sales.order`（订单），再把上游设计节点或关系绑定到它。
4. 在“下游：系统数据（可选）”创建运行数据投影，再定义对象类型，例如 `customer`（客户）和 `order`（订单），导入 CRM/ERP CSV，把字段映射为名称和外部标识。
5. 通过关系类型连接运行对象；点击“查询最短路径”检查跨对象链路是否成立。
6. 在“事件、指标与时间线”定义事件/指标并录入观测值，为后续分析提供时间依据。

### 岗位职责与流程工作设计

对每个关键岗位，企业投影 Agent 可以提出结构化的职责设计，包括：岗位承担的预期结果、职责为什么应由该岗位承担、该岗位拥有的决策权、需要与谁协同，以及依据来自哪份调研材料。职责不是岗位说明书里的动作清单，而是“结果—理由—权力—协同”的组合，后续调整组织架构时可以比较职责是否重复、缺失或放错位置。

对每个流程或流程步骤，Agent 会区分四种衡量方式：可量化、量化与定性混合、以定性判断为主、难以直接观测。评估可以记录指标定义、公式、单位、数据来源、局限和指标博弈风险；对于难量化工作，还可以记录定性信号和控制机制。

代理风险用于描述岗位目标和企业整体目标可能不一致的地方，例如只考核销售额导致低价签单、只考核关账速度导致跳过核对。每条风险记录形成机制、隐藏信息或行动、可能行为、领先信号和缓解办法。Agent 只形成待审批提案；批准后才写入投影。之后可以继续告诉 Agent 修改，系统按修订号防止旧提案覆盖新版本。

手工新增对象或关系会自动先创建 ChangeSet 草稿、校验，再一次性提交。需要批量建立对象时，可在“原子提交图变更”选择对象类型并填写多个名称，自动生成变更项；关系等复杂变更仍可编辑高级 JSON。

系统数据导入采用“发布设计基线 → 创建运行投影 → 文件读取 → 字段预览 → 本体/对象映射 → 人工确认 → 变更集提交”的固定流程。简单对象导入可以使用对象映射；需要一次生成对象、关系、事件和指标时，使用同一区域的“统一图谱映射”并填写声明式 JSON。确认后会保留源行、映射程序和对象血缘。

跨系统名称和编号不会被猜测合并。例如 `crm:C-001` 与 `erp:C-001` 默认是两个身份；只有在“跨系统身份桥接 JSON”中明确声明后，下一次预览才会考虑合并。这样可以避免不同系统的同名编号误连。

## 八、投影校验与发布

设计层发布只检查上游证据和建模是否足够；运行层是有系统企业的可选增强。发布门禁至少检查：

- 至少有一条已确认调研答案；
- 至少有一个企业设计节点（旧项目也兼容对象类型作为最小设计模型）；
- 运行投影若已创建，再单独检查对象、关系、导入、事件和指标质量。

后续的正式管理问题、因果、决策、行动和学习仍由后端领域服务承载；当前开发者主界面先聚焦“建模—对齐—发布”，避免在投影未形成前提前进入诊断。

早期记录的关注方向只是调研范围提示；正式管理问题必须包含症状、影响、证据引用、冲突或缺口和置信度。问题会先保存为候选状态，人工确认后才进入后续因果与决策流程。

## 九、管理层查询

1. 开发者发布后，打开 `/executive/`，先选择项目，再选择发布版本。页面只列出至少发布过一次的项目。
2. 新建管理咨询对话并提问。回答会显示引用的资源类型和 ID；没有依据时必须明确说明当前快照无法回答。
3. 发布新版不会覆盖旧版；旧版概览、哈希、条目和旧对话都保持不变。

后端仍保留发现、因果、决策、行动、Outcome、学习和报告服务，便于下一阶段在投影成熟后逐步开放对应页面；它们不参与当前开发者首页的启动加载。

## 十、当前边界

V3 当前不替代外部问卷系统的问卷填写界面。它已经具备本地核心闭环：调研导入、企业投影 Agent、结构化提案与受控执行、对象关系图、文件数据接入、因果/决策/行动、学习沉淀、不可变发布和高管管理 Agent 查询。

它还不具备现实 Palantir Foundry/AIP 的企业规模能力：实时 ERP/MES/CRM 连接器、分布式计算、向量检索、生产级后台任务、跨企业基准库和总部规模化飞轮仍是后续阶段。当前适合先用真实调研和文件数据完成管理层企业解读，再按价值接入系统。

## 十一、开源边界

真实问卷、答案、业务 CSV、数据库和本机数据目录都留在本地，不要复制到 GitHub。提交前运行：

```powershell
.\scripts\doctor-v3.ps1
python -m pytest backend\tests -q -p no:cacheprovider
python -m ruff check --no-cache backend\src backend\tests
```
