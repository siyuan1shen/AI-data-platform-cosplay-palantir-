# 岗位工作观察模块：最小开发方案

日期：2026-09-13。状态：规划，未实施本专项。按用户最新要求收缩范围。

本版替代本文此前的完整推广方案及 W00—W10 专项工作包。只开发一个“自动采集工作模式、简单对比”的模块；不建设员工上报、培训、推广、回执和效果追踪系统。平台其他既有能力保持不变，不因本次缩减而删除。

## 1. 两个目的，一个模块

1. 给岗位虚模持续补充实际工作记录：用了什么工具、常见操作顺序、不同做法及来源。
2. 让管理者直观看出方法差异，自行决定哪些值得了解、优化或推广。

员工电脑只安装独立的轻量采集工具，不安装、运行或登录本管理系统。一次启用后正常工作，不需要填写流程、标记任务、定期汇报或回答 Agent 的问题。企业只做一次基础配置：关联员工、岗位、电脑、需要观察的业务应用及数据交付方式。管理者可以在系统外与员工交流、传授方法，系统不跟踪这些活动。

这里识别的是“电脑上可观察的工作模式”，不是完整的业务流程或员工全部工作。电话、现场操作、思考等未观测活动保留为空白；不以增加员工填报补齐它们。

## 2. 只保留四项核心能力

### 2.1 自动采集

- Windows 轻量、可见的采集器记录前台业务应用及切换时间；需要识别浏览器业务页面时使用配套扩展。
- 浏览器只记录实际处于前台的活动页，使用业务域名/页面类型，不采集所有标签页或浏览历史。
- 员工/岗位关联使用已有公司模型，记录当时的关联，避免调岗后改写历史归属。
- 支持暂停、锁屏/无输入标记及断网缓存；重新连接后自动补传。
- 不记录键盘输入、不持续截图录像；不增加员工门户或日报表。
- 页面标题、文件名只在已配置的业务分类确有需要时本地提取；默认上传规范化活动类型，不上传完整网址参数等无关内容。

采集器是独立发布和安装的工具，只负责记录、暂存和传输，不包含管理系统前后端、企业数据库或 AI，不持续调用模型，不承担工作分析。它不得作为管理系统的内置运行组件，也不得依赖员工打开系统页面才能工作。需要浏览器页面识别时，扩展属于独立采集端。无需 ERP 接入即可开始；已有系统事件可以通过同一事件入口复用。

#### 独立部署与数据传输

部署分为员工侧的独立采集工具与管理者侧的系统。主系统只实现通用接收、导入与分析能力；通过版本化事件格式连接二者，不直接调用员工端进程，不要求共同部署。其他采集工具产生符合格式的数据时也能接入。

支持两条使用同一数据格式的交付路径：

1. **联网自动上传**：管理员一次配置接收地址和设备配对信息。采集工具在后台定期批量上传，例如每五分钟一次；接收服务验证设备所属公司及人员关联、持久化去重后返回回执。员工无须登录管理系统、上传文件或填报。设备凭据仅用于提交记录，不能进入管理后台或读取其他员工数据。
2. **离线数据包导入**：采集工具自动在本机指定目录生成标准数据包。管理员可以通过 U 盘、已有文件传输方式或企业共享目录集中收集，再由管理者在系统批量导入。员工不需要整理工作内容或逐日提交；完全隔离的电脑仍需要管理员承担实际拷贝，不能承诺无网络时自动到达另一台机器。

系统接收端必须在上传时可达。管理者电脑本地运行系统也可以作为接收端，但需另行启用局域网可访问的接收配置；当前形式的 127.0.0.1 地址仅指向每台电脑自身，不能直接填给员工电脑。不能为启用上传而顺带开放整个管理后台。也可以将接收端部署在企业自有常开主机，无须购买云服务或在员工电脑运行完整系统。

接收端关机或网络中断时，记录留在采集端缓存，恢复后补传。只有成功入库回执才能清除对应待传记录；本地缓存设置容量上限和可见异常状态，满载不得静默丢失。在线补传与离线导入采用同一事件标识去重，避免同一份记录被重复计算。

最小数据包包含格式版本、采集源/设备标识、事件标识、时间及会话顺序、规范化活动类别和覆盖/缺口信息；人员与公司归属由接收端根据已配置关联核对，不靠文件名或客户端随意填写的公司名称决定。

### 2.2 自动整理

程序根据简单、固定的应用/页面映射，把记录归为 CRM、表格、ERP、报价页面、邮件、自动化工具等活动类别。

按同一员工、同一连续观测区间排序，压缩重复活动，保留前台停留时间及来源。相同类别但明确不同的业务上下文不盲目合并；未知类别、锁屏、暂停、丢失采集等作为中断边界，不把中断前后拼成流程。

只统计相邻转换和连续 2—4 项的实际片段，不自动推断任务开始结束、客户身份或完整 SOP。同一员工多台电脑重叠且无法明确先后时，不拼接成一条序列。

### 2.3 工作地图与简单对比

一个页面即可：
- 上方选择公司、岗位、时间范围，查看该岗位常见工作路径。
- 选择两名员工，或一名员工与同岗位其他员工，查看方法差异。
- 点击路径查看具体出现片段、覆盖时间和来源。

第一版仅提供：
- 路径与相邻转换的出现次数。
- 使用过该路径的员工数量。
- 不同工具的前台停留时间及占已观测前台时间的比例。
- 数据连续且有效时的片段跨度，并明确它不是任务完成时间。
- 少见但重复出现的路径，避免只剩多数人的常见做法。

不新增绩效评分或“最佳流程”算法。管理者可以自己选择已知表现较好的员工来比较。路径短、使用自动化工具、绩效高，都不能单独证明方法更好。打开自动化工具也不等于自动化执行成功。

图上的边表示“实际观察到的先后转换”，不是业务因果、组织汇报或已完成交接；展示完整路径时必须有真实连续片段支持，不能由不同人的边拼出一条不存在的路径。

### 2.4 提供给虚模和现有 Agent

工作模式以“程序观测”形式关联到现有岗位虚模，不另建一套岗位/员工档案。

- 自动更新可测量的统计与证据摘要，不自动改变正式职责、权限或已确认的业务解释。
- 已有业务含义映射可以复用；没有映射时保留工具名称和未知含义，不要求员工补填。
- 管理者可以直接问现有管理 Agent：“这个岗位通常怎么工作？”“这两个人的方法有什么区别？”
- Agent 按需读取同一份统计和原始片段，解释差异并说明未覆盖的内容。
- Agent 的推测与程序测量分别标注，不把解释当成新事实。

不新增独立 Agent、不要求管理员逐条确认观测记录、不自动发起员工问答。已有模型编辑能力继续可用，但编辑不是本模块产生结果的前提。

## 3. 必须保留的统计边界

简化产品不等于省略影响结论的基础处理：
- 同公司、同岗位、同期间比较，明确双方采集覆盖和缺口。
- 不跨员工、跨公司拼接；岗位历史与设备重叠处理明确。
- 重传不重复计数；同一事件标识但内容冲突时记录问题，不静默覆盖。
- 时间不同步、采集重启和最后一个没有结束时间的片段不得产生虚假长耗时。
- 无输入不等于没工作，前台停留不等于工时；不可据此自动给员工排优劣。
- 不以序列出现次数推断订单/任务完成数；无案例标识时不声称“每项任务平均几步”。
- 有差异就展示差异；没有结果依据时不声称“效率提高多少”。

无需为了计算这些统计新增流程引擎、因果引擎或模型训练。采用可复核的确定性处理，按批次增量更新，不每次打开页面重建全部数据。

## 4. 与现有系统的最小接续

- 数据：存入现有观察库的工作观察表；保留事件、来源、分类版本和必要的统计结果。采集器本地缓存只是传输缓冲，不是另一套企业知识库。
- 虚模：引用工作观察结果，不复制出另一份流程事实；来自此模块的结论保留观察来源，不自动晋升正式企业事实。
- 后端：最少提供批量事件接收、标准数据包导入、岗位工作模式查询、对比查询；在线和离线共用入库与去重逻辑，查看路径时返回来源片段。耗时统计复用现有后台任务机制。
- Agent：仅添加读取模式和比较结果的工具，复用已有公司范围和证据引用规则，不扩充推广 Action。
- 前端：一个“工作模式”视图，复用现有图形组件；范围选择、图、差异列表和来源详情即可。
- 配置：复用设置入口，提供少量应用分类预设、员工/设备关联及独立采集端配置文件。管理者选择在线接收或离线导入；无需员工使用本系统，也无需普通管理者写规则或操作数据库。
- 留痕：人工调整分类或关联保留操作者与版本；展示统计时注明使用哪一版。没有人工操作则无需制造审批环节。

## 5. 明确不做

本模块不开发实践卡管理、培训课程、员工待办、站内推广、消息推送、阅读回执、采用率追踪、试点审批、推广批次、效果实验和自动绩效评估。

也不开发员工上报流程、任务手动打点、自动追问、复杂任务切分、屏幕录像理解或桌面自动执行。管理者在系统外交流和推广即可。

后续只有真实使用证明缺失某项能力会阻断“采集与对比”，才扩展它；不把上述删减项作为默认二期积压任务。

## 6. 开发顺序

1. **事件接收与统计**：固定最小事件格式、岗位关联和活动映射；实现在线接收与离线数据包导入，用模拟记录验证压缩、计数、缺口与重传。先保证数据算得对。
2. **独立自动采集工具**：单独打包发布 Windows 工具及配套浏览器扩展，验证切换、锁屏、暂停、跨机器上传和离线文件交付。员工测试电脑不安装管理系统，不能只用模拟数据或同机测试代替。
3. **单页地图与对比**：管理者选择岗位和员工即可查看，点击差异可以追溯记录。
4. **虚模与 Agent 读取**：关联同一份结果，验证无需员工填写任何表单，虚模就能得到新的可观测信息，管理者也能直接询问差异。

本轮仅修订方案，不开始上述实现。开发时保持既有前后端分工，先对齐事件和查询返回格式。

## 7. 最小完成标准

在两家模拟企业、多个岗位和真实 Windows 操作中验证：
1. 员工电脑未安装管理系统，完成独立采集工具的一次启用后，无须额外上报，管理者仍能在另一台机器看到记录。
2. 管理者在正常前端可以查看岗位地图，对比两种做法，找到真实出现的差异。
3. 虚模及 Agent 读取同一份结果，来源清楚，没有捏造业务含义。
4. 重复上传、断网、暂停、未知活动和调岗不会生成错误路径或重复统计。
5. 无 ERP、无绩效数据也能完成采集与对比，结果明确覆盖边界。
6. 不依赖 FDE 在后台补数据，也不依赖员工回答问题，才能显示结果。
7. 在线上传、接收端关机后的补传、离线包批量导入均可用；同一记录经不同路径到达时只计一次。隔离环境的人工拷贝由管理员完成，不伪装成自动传输。

交付目标到“看见真实可观察的差异”为止；企业自行判断、沟通和推广，不由本模块接管。
