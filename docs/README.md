# 设计文档索引

下一轮开发以 [41 完整重构方案（2026-09-15）](41-unified-refactor-scenario-actions-plan.md)为唯一总规格：一家公司维护一份企业投影，平台单库保留正式、观察和潜在认识的逻辑边界；两个用户级 Agent，建设 Agent 内部分建模与接入模式；统一情景推演、Action、独立工作观察和人工留痕。与 37、39、40 或其他旧规划冲突时以 41 为准。当前实施证据见 [42 重构实施记录](42-refactor-implementation-status-2026-09-16.md)；41 仍是总规格，不等于所有延期边界已经完成。当前 V3 操作参考 [31 使用手册](31-v3-user-manual.md)，历史验收见 [32 验收记录](32-v3-verification-report.md)，旧验收不能证明新方案已交付。

本文档集是项目建设的规划入口。产品首先服务核心管理层：从问卷、访谈和现场调研形成企业的初始数字投影，再按需接入业务系统；管理者据此查询、分析、推演和选择调整。可计算结果必须有明确规则与条件，潜在联系和因果假设不得冒充已证实事实。

## 当前取舍

- 集中建设企业建模、语义对齐、管理查询与探索、情景推演、内部 Action 和独立工作观察；历史企业案例按用户指定参考。
- 安全治理、复杂多租户、加密交换、云端高可用、扩展沙箱和微服务不作为当前产品模块或交付目标。
- 现有登录、凭据和本地数据边界只作为维持程序可运行的基础设施，不继续扩展，也不在当前阶段拆除。
- 所有新功能必须同时完成领域模型、数据库、API、前端、示例数据、测试和端到端演示；只有后端接口不算完成。
- 当前仓库只保留 V3 运行代码、迁移、启动链和必要契约；旧根目录 V1/V2 运行代码已删除，避免出现双运行路径。
- 后续编码以 41 号方案的 R0–R9 工作包和真实项目缺口为输入；任何“已完成”结论以对应版本的代码、前端流程及验收证据为准，旧验收不证明新功能已实现。
- 所有企业均可先建模再按需接系统；管理观察可随时输入，不要求先创建项目或填写正式管理问题。24 号及其他历史文档的流程描述仅在与 41 一致时参考。
