## 1. 使用方式与共同完成标准

按依赖执行 T00–T39。每个任务必须有：实现/变更说明、对应测试、实际运行结果、影响的 OpenAPI 操作、迁移/兼容说明、前端消费者、剩余限制。只有代码没有调用者、只有界面没有真实 API、只有 MOCK 没有声明测试边界，都不能标记完整交付。

表中路径为相对于 `D:\project\palantir` 的待修改范围，不表示新文件现在已存在。后端文件基路径为 `backend/src/enterprise_insight_backend/`；实现时优先扩展现有服务，按边界抽取新模块。BE = 后端；FE = 前端；QA = 共同验收。

每项开发顺序固定：核对最新代码与已有改动 → 加失败用例/契约例子 → 实现最小完整路径 → 运行针对性测试 → 运行受影响回归 → 更新契约/能力清单 → 接入真实消费者 → 记录结果。只有真实验证后才填写任务状态。

本任务单不安排自动推送 GitHub、不清空数据、不派发新任务，也不授权真实企业系统写入。跨窗口并行开发时，共享契约/迁移链只由一方合并。

## 8. 核心验收用例规范

### A01 · 不丢数据与领域约束

对同一对象仅改名，核对属性、证据与三方关系参与者完全不变；对洞察仅改状态核对原反馈。测试非法日期/UUID、父类必填、继承环、退役端点、跨项目引用、撤销证据、保留类型、null PATCH、已回答无答案和并发修订。预期 4xx 可读，不能 500、静默清空或部分写入。覆盖 T02/T03/T05。

### A02 · 空实例与材料

无模型配置时从前端创建并测试；导入每个 AVAILABLE 格式、中文编码 CSV、多工作表 XLSX、含表格 DOCX、文本/扫描/混合 PDF、损坏文件、空文件、同文件重传和多公司问卷。逐项核对正文/定位/行数/归属，unsupported 不可假成功。覆盖 T06/T11/T12/T20。

### A03 · Agent 真正完成建模

给定一个有 20 个对象、30 条关系、KPI、冲突陈述与未知项的合成企业：先生成草稿，批准前正式模型不变；一批批准后对象及引用正确；再说“调换某岗位上级并增加职责”，检查差异与回读。不以精确措辞匹配开放答案，但确定性事实和图不变式须符合标注。超过动作/上下文预算应继续或明确停点，不丢后半部分。覆盖 T13–T20。

### A04 · 上下文与发布

导入 45+ 片段后选择最后一个附件；关闭未确认材料；删除历史会话；同时排队新消息；发布后编辑草稿并导入新经营数据。逐次核对实际模型输入、工具读取、图、分析、导出全部使用正确 QuerySnapshot。最新经营数据可见不意味着最新设计草稿可见。覆盖 T10/T16/T18/T25。

### A05 · 来源、映射与重算

两个系统异码同物、一系统同名异物、跨系统同码异物；先无映射导入再补映射；使用相反来源导入顺序；同权威冲突；过期人工裁决；缺外键；source_asset 与文件名不同；映射升级、禁用和源 schema 漂移。比较最终统一身份、设计/现实值、冲突、血缘与记录统计。重复重算输出数量稳定。覆盖 T07/T08/T21–T25。

### A06 · 指标与时间

目标 95、实际 40 应计算未达标；同周期三次修订仍只有一期；三个独立可比时期才形成反复信号。增加相反方向指标、区间目标、非重叠年份、季度/月度、币种/单位差异、缺期、迟到修正及人工 status 冲突。图建 KPI 被分析识别，历史定义不被新目标改写。覆盖 T09/T26。

### A07 · 管理探索与反馈

准备只有设计风险、只有现实异常、双方支持、双方相反、资料缺失、合理取舍、代价越界、正常周期会议等案例。多个设计风险共享结果时不能顺序消耗。否定后同输入重跑不再新 OPEN；实质新证据达到重审条件才重开并展示差异。开放探索允许多解，不按固定规则清单限制所有思路。覆盖 T27–T30。

### A08 · 方案、实际执行和案例

创建两个不同组织调整方案，验证方案图改变、正式图不变；基线更新后重基处理冲突；批准应用改变设计，但实际视图仍等待现实证据。录入行动的成功/失败/副作用/未知结果，转案例；另一公司引用后只能出现参考来源和适用分析，不复制为该公司事实。覆盖 T31/T32。

### A09 · 任务和故障恢复

双 Worker/前端重复点击只产生一次有效写入；模拟模型超时、非法 JSON、任务取消、预演后对象被改、执行中数据库异常、程序重启、网络结果未知和单任务异常。验证预算、状态和检查点，Worker 不停摆、批准不过期乱用、任务失败无半批正式变更。覆盖 T14/T15/T17/T23/T37。

### A10 · 升级、恢复、部署

从现存每个迁移版本和明确已知的无版本 schema 升级；缺列/未知结构拒绝或正确修复，不伪盖章。生成项目包恢复到空实例，核对所有引用/历史；坏 hash、缺文件、越界路径、ID 冲突和半途失败不覆盖现有项目。干净安装、旧进程升级、端口占用与中文路径均验收。覆盖 T04/T34/T35。

### A11 · 评估真实性

用真实 Agent run 的材料、引用和动作日志评分；提交虚构 citation_count/action_keys 不能提高运行评分。将错误但有引用、正确但无足够支持、部分完成、等待审批、动作失败等区别计分。真实模型测试使用合成数据且单独记录模型、配置、时间、用量和预算，不把 MOCK 满分替代。覆盖 T33/T37。

### A12 · 性能

按主方案标准规模生成数据，在固定机器测列表/局部图 p50/p95、首次可交互、导入导出吞吐、峰值内存、数据库体积和 Agent 上下文实际大小。对翻倍数据检查增长趋势，确保分页、批处理、索引与快照缓存有效，排除模型外部延迟后再评估本地性能。覆盖 T36。

## 10. 关键检查点与不允许省略的人工判断

1. T01：确认设计/现实、KPI、QueryScope、问题身份的定义无冲突后再扩表；技术字段以主方案为准。
2. T04/T07：遇到来源不明旧记录只隔离并生成待复核清单，不猜测、不为了迁移通过而静默删除。
3. T14：批量修改批准范围明确；用户只是问问题，不自动转为正式写入授权。
4. T20：必须有一次完整前端录像/截图或可回放 E2E trace及接口结果，标明合成公司和项目，不能用后台脚本补漏。
5. T23：没有实际厂商系统样本时，只验收参考适配器；对具体 ERP 的兼容状态保持未知。
6. T33/T37：真实模型测试前明确调用预算和可发送数据；只用合成资料即可验收机制，不需要动真实企业资料。
7. T35：旧程序删除清单先按实际依赖核验，明确备份/归档方式，不能递归删除整个项目或历史数据目录。
8. T39：为每项保存实现、测试和结果链接；无法完成的必需项保持未完成，不能通过改名为未来功能规避验收。
