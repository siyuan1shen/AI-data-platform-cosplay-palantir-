## 真实模型传输路径补验

发现 `_invoke_model` 仍按字符截断序列化 JSON，可能丢失工具 schema、ID 和引用，且 MOCK 会绕过该路径。现改为完整紧凑 JSON；超过预算则不发网络请求，保存检查点并进入 BUDGET_EXHAUSTED。用户需提高配置或缩小任务范围后继续。HTTP 边界替身测试核对实际请求体可完整反序列化且数据不变，并核对超限不发请求；它验证传输程序，不是真实模型验收。

尚需完成的 T16 工作主要包括按相关性组织上下文、跨多轮的材料/图检索策略和完整覆盖/省略提示。当前超限暂停是避免发送残缺内容的修复，不能被计为大项目上下文能力已经完整交付。

多附件选材补验：修复多个附件按全局时间取最早 40 片段导致小附件被大附件挤掉的问题；改用按文档分组的窗口序号轮流选材，总数仍有界。每个上下文文档附 available_fragments/included_fragments，文本摘要附 text_truncated/original_char_count，并在真实模型提示中约束不得把局部阅读说成已读全部。45 片段大附件与 1 片段小附件同时选中时，验证实际入选为 39+1；Agent 回归 12 项通过，静态检查通过。材料和图邻域都已提供按需读取工具，并纳入下一轮模型上下文。

材料分批读取基础接口已增加 offset/limit，按 created_at/id 稳定排序，返回文档总片段数，负偏移和超范围 limit 拒绝。45 片段以 40+5 完整读取、无重复及非法偏移测试通过，现有不传分页参数的前端调用保持兼容。Agent 已注册 `read_material_fragments` 按需读取工具，工具结果会进入下一轮模型上下文；运行检查点和前端运行记录显示每份材料的已读/总片段数，并标出部分读取。新增 `read_graph_neighborhood` 按 Agent 查询快照按深度读取局部图谱，支持对象/关系数量上限及截断标记，验证 3 个对象/2 条关系的局部读取。单片段和局部图仍受 Agent 总上下文预算约束，超限会保存检查点而不是发送残缺上下文。
