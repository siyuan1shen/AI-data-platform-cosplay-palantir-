# 管理层企业决策投影总体规划

本文是当前项目的最高优先级规划。其他设计文档与本文冲突时，以本文为准。

## 1. 产品定位

产品只面向企业核心管理层及其调研、分析和改进团队。它不替代 ERP、CRM、MES、OA 或财务系统，而是在这些系统之上建立企业的管理认知层和决策层。

一句话定义：

> 通过管理层问卷、深度访谈和实地调研形成企业初始概念模型，再逐步接入各业务系统，用对象、关系、事件、指标、动作和因果假设构建企业的数字投影，帮助管理层更快理解企业、判断问题、选择行动并验证结果。

产品首先是“企业解读工具”，随后演进为“企业决策操作系统”。

## 2. 目标用户与参与者

### 2.1 主要用户

- 董事长、CEO、总经理；
- 核心经营班子；
- 战略、经营分析和数字化负责人；
- 负责重大改进项目的决策者。

### 2.2 数据和知识贡献者

- 调研顾问和企业分析师；
- 部门负责人和流程负责人；
- 财务、生产、销售、供应链等业务人员；
- ERP、CRM、MES、OA、财务等现有系统；
- 经过验证的行业模型、问题包和改进方案。

核心管理层是主要使用者，但不是唯一的数据录入者。管理层看到的是企业全景、关键证据、因果假设、决策选项和行动结果。

## 3. 核心价值

平台必须持续回答六类问题：

1. 企业由哪些关键对象构成，它们如何关联？
2. 企业的价值链、业务流程和信息流如何运转？
3. 当前发生了什么，哪些指标、事件和关系正在变化？
4. 为什么会发生，哪些只是相关，哪些具有因果证据？
5. 管理层可以采取哪些行动，各自的约束、成本和预期影响是什么？
6. 行动执行后是否有效，企业数字投影应如何更新？

北极星不是“收集了多少数据”，而是：

```text
Decision Improvement Yield
= 被管理层采用且结果得到验证的决策改进数
  / 调研、建模和分析投入
```

## 4. 产品边界

### 4.1 当前集中建设

- 管理层问卷、访谈和实地调研；
- 证据、陈述、事实、未知和冲突的区分；
- 企业对象、关系、事件、指标和动作本体；
- 企业数字投影及图查询；
- 数据源接入、转换、映射和血缘；
- 管理诊断、原因假设、情景模拟和行动闭环；
- Agent 协同、工具调用、计划执行和结果复盘；
- 因果假设、干预、对照和效果评估；
- 相似企业群组、行业基准和改进方案迁移；
- 企业内部与行业级数据飞轮。

### 4.2 当前明确不做

- 替代 ERP、CRM、MES、OA 或财务系统；
- 承担订单、库存、会计和生产交易主系统职责；
- 一开始建成覆盖企业所有细节的完整数字孪生；
- 将通用聊天机器人包装成管理决策平台；
- 在没有对象、关系和结果反馈的情况下追求 Agent 数量；
- 把登录、RBAC、ABAC、RLS、DLP、密钥、合规和高可用作为当前产品模块；
- 以微服务数量、模型大小或 Token 消耗衡量产品先进性。

现有代码中的基础身份、凭据保存和本地数据边界暂时保留，以维持程序运行；它们冻结为基础设施，不进入当前产品路线和资源投入。

## 5. 企业数字投影

企业数字投影不是一次性报告，也不是全量复制企业数据库。它是面向管理决策、随时间演进的企业模型。

### 5.1 投影的六类元素

| 元素 | 回答的问题 | 示例 |
|---|---|---|
| Object | 企业里有什么 | 公司、部门、员工角色、客户、产品、订单、设备 |
| Link | 对象如何关联 | 部门负责流程、订单属于客户、设备位于产线 |
| Event | 发生了什么 | 赢单、下单、排产、停机、交付、回款 |
| Metric | 状态如何衡量 | 毛利率、准时交付率、库存周转、投诉率 |
| Action | 可以做什么 | 调整排产、变更审批、启动改善项目、追加访谈 |
| Causal Model | 为什么及改变后会怎样 | 审批层级是否导致交付延迟 |

### 5.2 投影成熟度

```text
L0 调研画像
  管理层观点、组织和关键流程草图

L1 证据化投影
  观点关联问卷、访谈、文件和现场证据

L2 系统化投影
  接入业务系统，形成持续更新的对象、关系、事件和指标

L3 决策级投影
  加入风险、因果假设、情景、动作和结果

L4 学习型投影
  根据决策结果和同行经验持续改进模型、问题和方案
```

不要求一次达到 L4。每个企业从最小、可验证、对管理层有价值的投影开始。

## 7. 八个核心模块

### 7.1 Executive Research

管理问卷、访谈、现场观察、信息缺口和追问。输出企业初始概念、关键问题、待验证假设和接入优先级。

### 7.2 Ontology Language

定义 ObjectType、LinkType、EventType、MetricType、ActionType、Interface 和约束。它描述企业世界能表达什么。

### 7.3 Ontology Engine

管理对象和关系实例、版本、时间、图遍历、聚合、事件订阅、情景投影和动作结果。它使企业模型可查询、可组合、可运行。

### 7.4 Integration & Lineage

连接企业现有数据源，完成采集、结构分析、字段映射、实体解析、事件重构、质量检查和端到端血缘。

### 7.5 Decision Knowledge

区分 Statement、Observation、Fact、Hypothesis、Finding、Recommendation、Decision、Action 和 Outcome，避免把观点、模型输出和事实混在一起。

### 7.6 Causal & Scenario Engine

管理因果图、混杂因素、干预、对照、估计量、实验和反事实情景。输出有条件的影响估计，而不是把相关性包装成因果。

### 7.7 Agent Runtime

Agent 基于企业数字投影读取上下文、调用工具、生成计划、模拟影响、创建动作并复盘结果。Agent 能力从提案逐步演进到受控执行。

### 7.8 Learning & Peer Network

把企业项目中反复出现的问题、映射、风险模式、因果假设、Agent Recipe 和改进方案抽象成行业资产，并在相似企业中验证。

## 8. 端到端主流程

```text
0. 创建企业解读项目
1. 管理层问卷与访谈
2. 现场调研和证据采集
3. 建立初始对象、关系、流程和指标
4. 形成信息缺口与系统接入清单
5. 接入高价值数据源
6. 映射对象、关系、事件和指标
7. 形成企业数字投影
8. Agent 生成发现、原因假设和行动选项
9. 管理层选择行动并设定预期结果
10. 执行、采集结果并评估效果
11. 更新企业投影、因果模型和管理经验
12. 抽象可复用行业资产，指导下一次项目
```

详细角色、输入、输出和状态见[端到端业务流程](14-end-to-end-workflows.md)。

## 9. Agent 自主性阶梯

```text
A0 只读解释
A1 生成结构化提案
A2 调用分析、图查询和因果工具
A3 生成动作计划并模拟影响
A4 经管理层确认后执行可逆动作
A5 对低风险、重复性动作进行规则内自动执行
```

当前代码约为 A1。建设顺序不能跳过 A2 和 A3 直接追求自动执行。

## 10. 因果能力阶梯

```text
C0 描述与相关
C1 时序与前后比较
C2 匹配对照与准实验
C3 受控试点与自然实验
C4 可重复的因果策略
C5 因果驱动的情景优化
```

任何因果结论必须记录假设、适用范围、时间窗口、数据来源、混杂因素、估计方法和不确定性。

## 11. 相似企业指导

平台不复制另一家企业，而是建立 Peer Cohort：

- 行业和细分行业；
- 商业模式；
- 营收、人数、工厂或网点规模；
- 产品复杂度和订单模式；
- 供应链结构；
- 组织和流程成熟度；
- 信息系统成熟度；
- 当前问题和改进目标。

相似企业经验只能作为先验和候选方案：

```text
Peer Pattern
→ 与目标企业匹配度
→ 差距与适用条件
→ 候选改进方案
→ 目标企业小范围试点
→ 结果验证
→ 决定采纳、修改或拒绝
```

## 12. 建设优先级

### P0：决定产品是否成立

1. ObjectType、LinkType、EventType、ActionType；
2. 实体—实体 Link 和图查询；
3. Enterprise Projection 版本与时间视图；
4. 管理层调研到数字投影的完整流程；
5. Agent 基于本体工具工作，而不是仅总结文本。

### P1：形成真实价值闭环

1. 首个 ERP/CRM/MES 文件或 API Connector；
2. 可重放转换管道和血缘；
3. Finding → Decision → Action → Outcome；
4. 持久化 Agent Run、Evaluation 和 Flywheel；
5. 因果假设、干预和结果评估。

### P2：形成复利

1. 相似企业群组；
2. 行业基准、问题包和映射程序；
3. 改进 Playbook 迁移与试点；
4. 跨项目评测和学习；
5. 受控 Agent 执行。

## 13. 首个垂直场景

首个场景固定为“订单到回款”，避免同时覆盖全部企业：

```text
客户
→ 销售机会
→ 订单
→ 排产/采购
→ 生产/服务交付
→ 发票
→ 回款
```

首批对象：Company、Department、Customer、Product、Order、WorkOrder、Shipment、Invoice、Payment。

首批关系：OWNS、SERVES、PLACED_BY、CONTAINS、FULFILLS、PRODUCES、SHIPS、INVOICES、SETTLES、RESPONSIBLE_FOR。

首批事件：OpportunityWon、OrderCreated、PlanReleased、ProductionCompleted、ShipmentDelivered、InvoiceIssued、PaymentReceived。

首批动作：RequestEvidence、AssignOwner、StartImprovement、ChangeRuleProposal、RunScenario、VerifyOutcome。

## 14. 产品验收标准

首个可用版本必须完成：

1. 一次管理层问卷、访谈和现场调研；
2. 建立至少 5 种对象、8 种关系和 6 种事件；
3. 从两个来源映射到同一对象和流程；
4. 用图查询回答三个跨系统管理问题；
5. 生成一个可验证的原因假设；
6. 创建一个管理行动并记录结果；
7. 根据结果更新企业投影；
8. 把至少一个问题包、映射或 Playbook 复用于第二个项目。

如果无法完成上述闭环，增加更多 Agent、连接器或页面均不算产品进展。
