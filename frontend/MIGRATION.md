# 前端迁移方案

## 固定边界

- 新前端只位于 `frontend/`。
- 后端接口只使用 `/api/v3`。
- `../contracts/openapi.json` 是唯一接口标准，`src/api/schema.d.ts` 由它生成。
- 新前端不复制后端企业投影数据模型。
- 旧 `src/enterprise_insight/web/static_*` 页面在新页面通过验收前保持不动。

## 迁移方式

采用旁路替换，而不是直接重写旧页面：

1. 建立独立 React、TypeScript、Vite 工程与契约生成流程。
2. 先打通公司、项目、双端切换和使用者草稿预览。
3. 迁移材料导入和预览确认。
4. 迁移企业投影 Agent、运行状态与提案审核。
5. 迁移系统接入、语义映射、冲突和未知项。
6. 迁移校验、差异、发布及正式使用端。
7. 完成管理 Agent、潜在关系、情景和行动结果。
8. 所有新页面通过浏览器验收后，再由整体重构任务移除旧页面。

## 页面归属

### 开发建设控制台

- 公司与项目
- 材料与导入
- 建模 Agent 与提案审核
- 系统接入与语义映射
- 校验与发布

开发端不建设第二套企业投影图，只提供“以使用者视角预览”。

### 管理层使用端

- 企业数字投影
- 已对齐的企业数据、事件和指标
- 管理 Agent
- 问题、假设、情景、行动和结果

## 每页验收门槛

- 类型检查通过。
- 契约相关单元测试通过。
- 真实浏览器中完成主要操作路径。
- 每个可点击控件有真实行为或契约一致的 Mock 行为。
- 加载、空状态、失败状态和成功状态均可读。
